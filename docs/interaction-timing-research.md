# 引导时机与表达状态感知：全网深度研究

> 日期：2026-06-14
> 定位：回答"什么时候该引导"这个核心问题

---

## 0. 问题重述

之前的方案犯了一个根本性错误：把引导当成对"关键词"的反应。

```
❌ 错误模型：用户说"那个东西" → 触发引导
✅ 正确模型：用户在某个点上犹豫/绕圈/停顿 + 这个点值得深挖 → 在合适间隙引导
```

关键词只是表象，真正的判断维度是**表达状态**和**内容价值**。

---

## 1. 表达状态感知

### 1.1 流畅表达 vs 犹豫表达

#### Goldman-Eisler（1968）：停顿的心理语言学

Goldman-Eisler 的经典研究区分了两种停顿：

| 停顿类型 | 位置 | 时长 | 含义 |
|---------|------|------|------|
| **呼吸停顿（Breath pause）** | 语法边界（句号、逗号处） | 200-500ms | 正常的语言产生过程 |
| **犹豫停顿（Hesitation pause）** | 语法单元内部 | 500-2000ms | 认知负荷高，在组织语言 |
| **规划停顿（Planning pause）** | 句子开头 | 1000-3000ms | 在规划要说什么 |

**关键洞察**：只有"犹豫停顿"才是引导时机。呼吸停顿是正常的，不应干预。规划停顿是用户在思考，应该等待。

#### Maclay & Osgood（1959）：犹豫现象的分类

他们识别了四种犹豫现象：

1. **重复（Repetition）**："我...我觉得..." — 在组织语言
2. **错误启动（False start）**："我觉得应该...不是，我的意思是..." — 在修正自己
3. **填充停顿（Filled pause）**："嗯..."、"那个..." — 在思考
4. **非填充停顿（Unfilled pause）**：沉默 — 在思考

**关键洞察**：重复和错误启动说明用户在挣扎，可能是引导时机。填充停顿说明用户在思考但不一定需要帮助。非填充停顿需要结合上下文判断。

#### Clark & Wasow（1998）：停顿的"承诺"理论

他们提出：说话者在每个词之后都有一个"承诺点"（commitment point）。在承诺点之前停顿是正常的（在规划），在承诺点之后停顿是异常的（在犹豫）。

**对专访的启示**：引导应该在"异常停顿"处触发——即用户在已经承诺了一个方向后突然犹豫。

#### Levelt（1989）：语言产生的三阶段模型

Levelt 的语言产生模型分为三个阶段：

1. **概念化（Conceptualization）**：想清楚要说什么
2. **形式化（Formulation）**：组织成语言
3. **发音（Articulation）**：说出来

犹豫可能发生在任何一个阶段：
- 概念化犹豫 → 用户不知道要说什么 → 可能需要引导
- 形式化犹豫 → 用户知道要说什么但不知道怎么表达 → 可能需要帮助
- 发音犹豫 → 用户在找词 → 应该等待

**关键洞察**：只有"概念化犹豫"才需要引导。"形式化犹豫"和"发音犹豫"应该等待。

### 1.2 韵律特征与表达状态

#### Shriberg（1994）：韵律与话语结构

Shriberg 发现，韵律特征可以预测话语结构：

- **音高重置（Pitch reset）**：新话题开始的信号
- **末尾延长（Final lengthening）**：话轮结束的信号
- **语速变化（Speech rate change）**：认知负荷变化的信号

**对专访的启示**：
- 音高重置 → 用户在切换话题 → 可能需要引导拉回
- 末尾延长 → 用户快说完了 → 准备追问
- 语速变慢 → 用户在深思 → 不要打断
- 语速变快 → 用户在流畅表达 → 不要打断

#### Local & Kelly（1986）：犹豫的韵律标记

他们发现犹豫有特定的韵律标记：

- **平调（Level tone）**：在犹豫处，音高趋于平坦
- **音量下降**：犹豫时音量通常下降
- **语速骤降**：犹豫前语速突然变慢

**对专访的启示**：这些韵律特征可以作为引导时机的信号。

#### Swerts（1998）：韵律与话轮转换

Swerts 发现，话轮结束有特定的韵律标记：

- 音高下降 + 末尾延长 + 停顿 = 话轮结束
- 音高持平 + 无延长 + 停顿 = 话轮未结束（思考停顿）

**对专访的启示**：区分"话轮结束停顿"和"思考停顿"是引导时机的关键。

---

### 1.3 语义特征与表达状态

#### Beattie（1983）：犹豫的语义关联

Beattie 发现犹豫更常出现在：

- 抽象概念之后
- 情感词汇之后
- 转折点之前
- 新信息之前

**对专访的启示**：如果用户在说了抽象概念后犹豫，说明这个概念值得深挖。

#### Bortfeld et al.（2001）：犹豫与认知负荷

他们发现犹豫频率与认知负荷正相关：

- 描述简单事件 → 低犹豫率
- 解释复杂关系 → 高犹豫率
- 表达矛盾情感 → 最高犹豫率

**对专访的启示**：犹豫频率本身就是信号——高频犹豫说明用户在思考复杂问题，可能需要引导帮助理清。

## 2. 引导时机：人类采访者的实践

### 2.1 什么时候该引导？

基于对顶级采访者的分析（Terry Gross, Oprah Winfrey, Louis Theroux, 白岩松, 柴静），总结引导时机：

| 时机 | 信号 | 引导方式 | 示例 |
|------|------|---------|------|
| **用户绕圈** | 同一观点重复 2-3 次 | 结构型引导 | "你反复提到X，核心是什么？" |
| **用户模糊** | 使用模糊词后停顿 | 锚点追问 | "等一下，你说的X具体是指？" |
| **用户矛盾** | 前后不一致 + 犹豫 | 矛盾标记 | "你刚才说X，但现在说Y..." |
| **用户回避** | 切换话题 + 语速变快 | 拉回引导 | "我们先不急着换话题..." |
| **用户情绪** | 情感词汇 + 停顿 | 共情标记 | "听起来这件事对你很重要" |
| **用户迷失** | 长段表达 + 无结论 | 阶段总结 | "到目前为止，核心是..." |
| **用户停顿** | 长停顿 + 无填充 | 轻推 | "嗯"、"然后呢？" |

### 2.2 什么时候不该引导？

| 时机 | 信号 | 原因 |
|------|------|------|
| **流畅表达** | 语速稳定 + 无停顿 | 用户在正常表达，不应打断 |
| **正常停顿** | 语法边界停顿 < 500ms | 正常的呼吸/组织停顿 |
| **正在组织** | 填充停顿（"嗯..."） | 用户在思考，应等待 |
| **情绪释放** | 哭泣/长叹/激动 | 应给予空间，不急于引导 |
| **刚被引导过** | 距上次引导 < 5 秒 | 避免过度干预 |
| **AI 正在说话** | AI 在表达 | 不应插入（除非用户打断） |

## 3. 全双工交互模型

### 3.1 不是"回合制"，是"持续感知 + 适时干预"

真正的全双工交互不是：

```
用户说 → AI 说 → 用户说 → AI 说（回合制）
```

而是：

```
用户持续表达 ──────────────────────────────────────→
AI 持续感知：韵律、语义、表达状态、内容价值
AI 适时干预：在自然间隙插入引导/打断/附和
AI 持续输出：追问回复、TTS 播放
```

### 3.2 干预的"窗口"模型

引导和打断不是在任意时刻发生的，而是在特定的"干预窗口"：

```
用户表达时间线：
|══════ 流畅表达 ══════|── 停顿 ──|══ 继续 ══|──── 长停顿 ────|══ 流畅 ══|
                        ↑           ↑          ↑
                     窗口1:      窗口2:      窗口3:
                    "嗯"轻推    锚点追问    阶段总结
                   (不夺权)    (不夺权)    (不夺权)

AI 说话时间线：
|══════ AI 追问 ════════════════════════════════════|
    ↑                ↑                      ↑
  窗口4:           窗口5:                 窗口6:
 用户说"嗯"       用户说"不对"          用户说完整句子
 → backchannel    → 打断                 → 打断
 (AI继续)         (AI停止)              (AI停止)
```

**关键洞察**：干预窗口由"位置"（在谁的话轮中）+ "时长"（停顿多久）+ "内容"（说了什么）三者共同决定。

### 3.3 统一的干预决策矩阵

```
                    用户流畅表达中    用户停顿中      AI 说话中
                    ─────────────    ──────────     ─────────
用户说短词(<500ms)     忽略          可能是轻推      backchannel
用户说模糊词           忽略          锚点追问        可能是打断
用户说转折词           忽略          矛盾标记        可能是打断
用户说完整句子         忽略          话轮结束        打断
用户沉默               N/A           等待/轻推       N/A
```

**核心原则**：
- 用户流畅表达中 → **永远不干预**
- 用户停顿中 → **可以引导，但不夺权**
- AI 说话中 → **只有明确打断信号才干预**

## 4. 实现方案：表达状态感知引擎

### 4.1 表达状态分类

```typescript
type ExpressionState =
  | "fluent"           // 流畅表达：语速稳定，无异常停顿
  | "organizing"       // 组织语言：填充停顿（"嗯..."），正常
  | "hesitating"       // 犹豫：异常停顿 + 模糊词/重复
  | "circling"         // 绕圈：同一观点重复
  | "emotional"        // 情绪化：情感词汇 + 韵律变化
  | "concluding";      // 收尾：末尾延长 + 音高下降
```

### 4.2 表达状态检测

```typescript
function detectExpressionState(input: {
  // 韵律特征
  speechRate: number;           // 当前语速 vs 基线语速
  pitchTrend: "rising" | "falling" | "flat";
  energy: number;               // 音量
  
  // 停顿特征
  currentSilenceMs: number;
  pausePosition: "grammar_boundary" | "mid_clause" | "sentence_start";
  
  // 语义特征
  hasFilledPause: boolean;      // 是否有"嗯..."等填充停顿
  hasRepetition: boolean;       // 是否有重复（"我...我觉得"）
  hasFalseStart: boolean;       // 是否有错误启动
  hasVagueTerm: boolean;        // 是否有模糊词
  hasEmotionWord: boolean;      // 是否有情感词
  hasContradiction: boolean;    // 是否有转折
  
  // 历史特征
  samePointCount: number;       // 同一观点重复次数
  timeSinceLastGuidance: number; // 距上次引导时间
}): ExpressionState {
  // 流畅表达
  if (input.speechRate > 0.8 * baselineRate && 
      input.currentSilenceMs < 500 &&
      input.pausePosition === "grammar_boundary" &&
      !input.hasRepetition &&
      !input.hasFalseStart) {
    return "fluent";
  }
  
  // 组织语言
  if (input.hasFilledPause && 
      input.currentSilenceMs < 800 &&
      !input.hasVagueTerm) {
    return "organizing";
  }
  
  // 犹豫
  if ((input.hasVagueTerm || input.hasRepetition || input.hasFalseStart) &&
      input.currentSilenceMs >= 500 &&
      input.pausePosition === "mid_clause") {
    return "hesitating";
  }
  
  // 绕圈
  if (input.samePointCount >= 2) {
    return "circling";
  }
  
  // 情绪化
  if (input.hasEmotionWord && 
      (input.energy > 1.3 * baselineEnergy || input.pitchTrend === "flat")) {
    return "emotional";
  }
  
  // 收尾
  if (input.pitchTrend === "falling" && 
      input.currentSilenceMs >= 800) {
    return "concluding";
  }
  
  return "fluent";
}
```

### 4.3 引导决策：表达状态 → 引导动作

```typescript
function decideGuidance(state: ExpressionState, context: {
  hasDeepValue: boolean;        // 当前内容有深挖价值？
  isBlindspotRelated: boolean;  // 与盲区相关？
  isDebtRelated: boolean;       // 与知识债相关？
  guidanceBudget: number;       // 剩余引导配额
}): GuidanceAction | null {
  
  switch (state) {
    case "fluent":
      return null; // 永远不干预流畅表达
    
    case "organizing":
      return null; // 等待用户自己组织
    
    case "hesitating":
      if (context.hasDeepValue && context.guidanceBudget > 0) {
        return { kind: "anchor_probe", priority: "medium" };
      }
      if (context.guidanceBudget > 0) {
        return { kind: "nudge", priority: "low" };
      }
      return null;
    
    case "circling":
      if (context.guidanceBudget > 0) {
        return { kind: "mini_summary", priority: "high" };
      }
      return null;
    
    case "emotional":
      return { kind: "emotion_label", priority: "medium" };
    
    case "concluding":
      return null; // 用户快说完了，等话轮结束再追问
    
    default:
      return null;
  }
}
```

## 5. 最终架构

```
═══════════════ 全双工时间线 ═══════════════

AI 说完上一轮追问
    │
    ├── LLM 生成预判信号（内容价值标注）
    │   "下一轮用户可能涉及：盲区X、知识债Y、矛盾Z"
    │
    ▼
用户开始说话 ──────────────────────────────────────────→
    │
    ▼
持续感知层（每 100ms）：
  ├── 韵律：语速、音高趋势、能量
  ├── 停顿：时长、位置（语法边界/句中/句首）
  ├── 语义：填充停顿、重复、错误启动、模糊词、情感词
  └── 输出：ExpressionState（流畅/组织/犹豫/绕圈/情绪/收尾）
    │
    ▼
当 ExpressionState ≠ "fluent" 时：
  ├── 检查内容价值（LLM 预判信号）
  ├── 检查引导预算
  └── 决定：引导 / 等待 / 忽略
    │
    ▼
引导触发时：
  ├── 选择引导话语（LLM 预判或规则 fallback）
  ├── 前端展示引导指示器
  └── 可选 TTS 叠加播放
```

**核心改变**：从"关键词触发"变成"表达状态感知 + 内容价值判断"。

## 6. 与 LLM 预判的关系

LLM 预判信号不再预测"用户会说什么词"，而是标注"下一轮哪些内容值得深挖"：

```
<pre_signals>
depth_targets:
  - concept: 授权机制
    reason: 用户反复提到但从未定义
    guidance: 你说的"授权"具体是指什么？
  - concept: 短期代价
    reason: 盲区候选，用户一直在回避
    guidance: 如果放手，最坏会怎样？
backchannel_whitelist: 嗯,对,是的,好
interrupt_sensitivity: low
</pre_signals>
```

实时阶段：表达状态引擎检测到"犹豫" + 犹豫内容匹配 depth_targets → 触发引导。

## 7. 验收标准

- [ ] 用户流畅表达时，系统不发出任何引导
- [ ] 用户组织语言时（"嗯..."），系统等待
- [ ] 用户犹豫 + 内容有深挖价值时，系统在停顿处引导
- [ ] 用户绕圈时，系统做阶段总结
- [ ] 用户情绪化时，系统做共情标记
- [ ] 用户说 backchannel 时，AI 不停止
- [ ] 用户说打断触发词时，AI 立即停止
- [ ] 两次引导间隔不少于 5 秒
