## 0. 先厘清:两套 P 编号,别混

本体论库里 P1-P4 出现过两次,走的是**不同的层**——这是读懂"做了没做"的前提。

## 2. 真正的欠账(本体论增值未兑现)

骨架(A/B/C/E/F 的边与公理)立住了。**本体论真正承诺的"新解锁能力"全部还没动**:

### 欠账①【P3·根因】attributeThemeIds 下线 + LLM 直出受控三元组
- **现状**:`attributeThemeIds`(finalize-llm.ts:222)用 `theme.name` ≥3 字符子串 includes + fallback themes[0] 猜归属 → 喂给 belongs_to_theme 边。
- **本体论要求**(01 §7 P3 明列"抽取产出**受控三元组**,attributeThemeIds **下线**"):finalize 的 LLM 应**直接产出三元组**(资产 —belongs_to_theme→ 主题,带 provenance.origin),而非事后子串猜。
- **为什么是根因**:belongs_to_theme 是图召回(recallThemeAssets)的全部依据。源头是脆弱子串 → 整条图召回精度被封顶(GIGO)。这一步同时让"关系一等化"名副其实(边有可信来源,而非猜测副本)。

### 欠账②【P3·新能力】轻量推理:矛盾检测 + 主题演化
- contradicts(同主题下对立 Point → 生成边 + 提示复盘)、evolves_into(主题时序演化 + 传递闭包时间线)——**01 §5.3 标的"新解锁认知能力",01 §6 标的"推理层",至今 schema 空建无生产者**。
- 这是本体论相对"一堆数组"的**核心增值**。不做,本体化只换来"结构更整齐",没换来"系统能推出你没明说的东西"。

### 欠账③【P2】混合检索 + 加权邻域召回
- **混合检索**(03 §5 P2 明列):memory/rag_chunk 的 BM25 索引已建却闲置,召回只用 HNSW。本体论路线要 `search::rrf` 把图 + 向量 + 全文融合。
- **加权邻域**:recallThemeAssets 单跳,应升级为用 belongs_to_theme.weight 的加权多跳邻域遍历(01 §6"加权邻域遍历替代手工列举")。
- (本条即前一份技术诊断的 search::rrf——**它本就在本体论 P2 主线内,是欠账,不是题外优化**。)

### 欠账④【原子D·正交】家族树域层落地
- 域层建 CognitiveEntity/Distillation 父类,让 export/purge/敏感过滤/证据/召回对"蒸馏类"**写一次**而非四类各抄一遍。当前 12 平行数组,共性逻辑仍重复。

### 欠账⑤【原子B·补全】provenance.origin 真区分
- derived_from.origin 写死 llm_extracted → 修为按"LLM 抽 / 用户确认 / 导入"真实赋值。否则 A3(归因门控)在溯源边上形同虚设(现 checkA3 只能退而用 memory.status 旁证)。
