## 三、待决策的设计权衡(已找出,附修法 + 为何未在本次实施)

> 这些是**大架构 / 需方向决策 / surreal 未上线非紧急**的项。在一次 session 内鲁莽实施会引入回归风险或越过产品决策,故列出修法与优先级供决策。

### 高优先级 —— surreal 权威上线前必须解决

**H1. 降冷 turns → 溯源召回失效(影响 P2b 溯源)**
- 现象:`offloadCompletedSession` 剥离 `session.turns` 与 finalize 同批 `replaceState`;`collectEdges` 用内存 `turnIds` 过滤 `derived_from`/`part_of`,`turnRecordsOf` 也从 `state.sessions[].turns` 摊平。turns 清空后 → 溯源边全被过滤 + turn 节点不写 surreal → `recallProvenanceTurns` 恒返回空 → P2b 溯源在 surreal+降冷生产配置下不可用。连确认进长期记忆的 MemoryRecord 溯源边也随 session 降冷被删。
- 修法:turn 作为 append-only 冷层 occurrent,**独立于热 state 降冷**写入/保留在 surreal(降冷前单独通道);或 `derived_from` 投影信任 `anchor.turnId`(不用内存 turnIds 过滤)且保证 turn 节点持久。
- 为何待决策:涉及 SurrealStore persist + 降冷流程架构改;surreal 权威默认未启用(sqlite),非紧急但上线前必修。

**H2. relatedThemeIds 写入完备性(原生召回读写契约)**
- 现象:`recallThemeAssets` 的 point/decision/question 完全依赖 `belongs_to_theme` 边(唯一来源是 `relatedThemeIds[]`)。若资产创建时 relatedThemeIds 未可靠填充,原生召回漏召回该资产(sqlite 回落靠子串仍能召回 → 不等价)。
- 修法:审计 finalize / 资产创建链路,确保 relatedThemeIds 落库前填充(`attributeThemeIds` 覆盖度);或原生分支补子串兜底。
- 为何待决策:需专项审计资产创建链路,是 surreal 权威上线前的验证项。

### 中优先级

- **M1. 记忆↔主题建模不统一**:MemoryRecord 走 `MemoryEdge` 独立表,其余七类走 `relatedThemeIds` 内嵌,两套形态表达同一"属于主题"语义,消费侧(recallThemeAssets)维护两条分裂路径。建议统一(搭后续图重构;`docs/ontology/02` 的 OntologyGraph 投影是目标形态)。
- **M2. voice 路径未接 provenance**:P2b 溯源只进 `card.historyReferences`;`buildInterviewAgentContext`(语音 agent-context)未消费 `provenanceTurns`。建议 guide/agent-context 也纳入证据原话,让语音专访能引用受访者原话。
- **M3. KnowledgeDebt 缺 appearances + 债不去重**:`finalize` 债是纯 prepend(同概念会重复),不像主题 upsert。建议引入债 upsert(按 concept)+ `appearances`,与主题对称。**需产品确认是否债去重**。
- **M4. 性能:createSessionDraft 重复 build contextPack 3-4 次**:card 与 guide 各自 build,`buildPerspectiveCoverage` 把全语料拼大字符串 × 35 signal 每次重算。建议复用 contextPack/记忆化 perspectiveCoverage。
- **M5. surreal/sqlite 召回不等价**:surreal=图精确归属(不漏不误但依赖 relatedThemeIds 完备),sqlite=子串宽松。本质权衡,需确认可接受 or 统一(与 H2 关联)。
- **M6. themeAssets.memories 继承 token 启发式**:`about_theme` 边来自 `buildMemoryEdgesForRecord` 的 token 重叠(≥2)启发式,非真向量召回;与 memoryHits(HNSW)并集时会被启发式结果稀释。建议明确定位或以 memoryHits 为主。

### 低 / 需产品决策

- **L1. RELATE 无 ENFORCED**:关系表 P0 有意不约束 IN/OUT,DB 层可写悬挂边(当前靠应用层 known-id 集兜底)。建议端点类型确定的边(part_of/about_theme/belongs_to_theme)加 `ENFORCED`。
- **L2. DecisionAsset `decisionKind` 与 `confirmationStatus` 疑似冗余**:当前永远同步翻转。需产品确认是否区分"用户原创决策 vs 确认的 AI 候选";若需要,confirm 时不应覆盖 decisionKind。
- **L3. relatedThemeIds 可空性不统一**:point/question 必填 `[]`,decision/debt/note/session/importSource 可选。建议统一必填 `[]`(消除消费端判空分叉;改动面=所有创建点 + normalize)。
- **L4. memoryHits.text 冗余**:`RecallResult.memoryHits` 携带 text 但消费侧只用 id。建议删 text 省带宽,或在内存 record 缺失时用 text 兜底。
- **L5. intent null 风险 / lastPersisted 持引用**:edge-mapper `turnRecordsOf` 无条件写 `intent`(将来 null 会致 surreal coerce 失败、双写发散);persist 基线持 snapshot 引用(约定不 mutate,非结构保证)。均为脆弱点,非当前 bug。
