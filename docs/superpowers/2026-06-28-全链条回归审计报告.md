## 1. 已亲手验证为真(最高置信)

### A · ② 矛盾检测/观点演化 = 半死功能(投入产出失衡)
- **验证**:`opinionEvolution`/`graphReferences` 在前端(src/ 非域层)**零渲染**(rg 排除域层后 0 命中);`guidanceState.kind` 只被设为 `"nudge"`(App.tsx)——"发现矛盾"徽标(InterviewView.tsx:191)等 4/5 徽标永不亮;唯一到达路径是 LLM prompt(bailian.ts 2 处)+ voice(voice-instructions.ts 1 处)隐式注入。
- **事实链**:② 做了完整后端(reasoning.ts 规则筛 + cognitive-relations-llm.ts LLM 精判 + applyCognitiveRelations 双向写 contradictsPointIds + buildOpinionEvolution 做实)+ **每次 /end 花 LLM 成本**,但:① 采访 UI 不呈现"系统发现你的矛盾/观点变化";② 离线策略引擎 `turn-builder.ts:266` 直接 `opinionEvolution:[]`、`strategy.ts` 不读 contradicts;③ 资产库无"对立/演化"视图。
- **结论**:仅当配了 LLM key 且走 LLM 追问时,② 才隐式影响提问措辞。**投入(LLM 成本+复杂度)与产出(用户几乎看不到)严重失衡。**
- **决策点**(需你定):要么在采访 UI / 资产库做"矛盾与演化"呈现(让 ② 真正可触达),要么接受"仅 LLM 隐式"并停止扩张,要么回退 ②。

### B · 日期类型损坏(dual-surreal 切换引入)
- **验证**:spike 实测 SurrealDB `datetime` 列写入 `Date` 后,`SELECT` 读回是 `DateTime$1`(SDK 包装类),`typeof==='object'`、`instanceof Date===false`。
- **事实链**:updatedAt/createdAt/startedAt/timestamp 不在 node-mapper `core`、只作 ISO 进 rest blob;但 schema 又声明了 typed datetime 列(001_nodes),`fillUpsertDefaults` 把 ISO 转 Date 写进去;`loadState` 的 `SELECT *` 读回 typed 列(DateTime$1)经 `fromRecord` 的 `{...rest,...core}` **覆盖** rest 的 ISO string;`normalizeProductState` 不 coerce 回 string。
- **触发**:surreal 权威(dual-surreal)**进程重启后** getState 的日期是 DateTime$1,域类型声明 string → 任何 `.slice()`/字符串比较/`localeCompare` 消费点行为异常或抛错。运行时(不重启)因 getState 返回内存副本(string)暂不触发。
- **掩盖**:`JSON.stringify(DateTime$1)`→ISO 让 digest 比对发现不了;reload 测试(surreal-repo.test:91-104)只断言 title/relatedThemeIds,漏断言 updatedAt。
- **修法**:`fromRecord` 或 `normalizeProductState` 把 datetime 列 coerce 回 ISO string;并给 reload 测试补 updatedAt 断言。

## 2. 高置信真问题(代码确认)

### C · ② applyCognitiveRelations 覆盖用户已确认的 status
`src/domain/reasoning.ts:117-119`(被挑战中)、`:122-129`(已修正)。弱方降级守卫 `TERMINAL_POINT_STATUSES` 仅含 `已放弃`,不看 `confidence==='用户确认'`。用户手设 `稳定观点`+`用户确认` 的 point 被 LLM 判对立 → status 静默改 `被挑战中`;supersede 分支无任何确认守卫。**一次 LLM 判定可推翻用户明确确认。** 修:弱方降级/取代前检查 `confidence!=='用户确认'`。

### D · 溯源原话绕过 A4 门控(真实泄漏面)
`recallProvenanceTurns`(surreal-repo:143)`SELECT VALUE ->derived_from->turn.*` 返回 turn 原话 → prefetch → context-pack `provenanceTurns` → `buildInterviewCard` 拼进 `historyReferences` → LLM。turn 表无 sensitivity、不校验来源资产当前 status/sensitivity。**资产后被标 sensitive/deprecated,其证据 turn 原话仍经溯源通道进模型上下文。** 修:溯源时校验 anchor 资产当前 status/sensitivity,或对 provenance 施加门控。

### E · dual-surreal 权威库写失败静默吞 + 比对盲区
`surreal-repo:91-101`(enqueuePersist 的 .catch 仅 console.error)+ `dual-write-repository.ts`(replaceState fire-and-forget)。surreal 是权威库时,persist 抛错只打日志、不回滚、不反映到 200 响应;divergence 比对(`dual-write-repository.ts:26,36`)读的是两个**内存** getState(都过 normalize),**不验证 surreal 是否真落盘**。finalize 后若不再写且进程重启 → 该次资产/记忆永久丢失。修:权威库写失败要反映到响应/告警,或比对纳入持久层校验。

### F · decisions/debts/questions 永无 evidenceAnchors → 无溯源(A1 无判别力)
`finalize.ts:214-240` 只对 points 做 evidence→anchor 二次解析、note 补 keyQuoteAnchor、theme 补 representativeQuoteAnchor;decisions/debts/questions 的 LLM 输出无 evidence quote、也不二次回填 → `edge-mapper` 对 decision/debt 投影 derived_from 时 `evidenceAnchors` 恒 undefined → **这三类资产永远没有溯源边**,A1 公理对它们形同虚设。

### G · embedding 归一化不一致(B2 + 切换)
本地 bge `normalize:true`(local-embedding.ts:43),云端 DashScope 请求只发 `{model,input}`(bailian.ts:1387)**不归一化、不显式锁 1024 维**。HNSW 是 COSINE。**切换 EMBEDDING_PROVIDER 或 dual 混用旧记忆时,旧 embedding 与新查询向量不同源/不同尺度 → 语义召回退化无告警。** 且维度靠"默认恰好 1024"隐式对齐。修:云端显式 `dimension:1024` + 确认归一化语义一致;切换 provider 应提示重算存量 embedding。

### H · 业务流:生产鉴权下前端全 401(部署阻断)
`src/api/productApi.ts` 所有请求不附 `Authorization`,前端无 token 存储;server.ts 在 `DEPLOYMENT_PROFILE=production`+token 下强制 bearer。**一旦正确配置生产鉴权,前端每个 API 调用全 401,产品不可用。** 当前"能用"仅因 dev fail-open。属生产阻断级(单用户本地暂不触发,但部署即炸)。

### I · 业务流:创建 session 同步 await embedding,本地冷启动卡 ~20s
`interview-sessions.ts:122` 在响应前 `await embedQueryText`;本地 embedding 首次 `pipeline()` 加载模型 ~20s(我端到端实测首次 1.6s 是缓存命中后、冷加载更久)。LLM card enrichment 已移出关键路径(:136-139),**embedding 没有**。无 timeout 降级。修:把 embedding 移出创建关键路径,或加超时回落关键词召回。

### J · supersededByPointId 无边投影 + ④ collectCognitiveEntities 死代码
② 的"取代"关系只写进 `PointAsset.supersededByPointId`,edge-mapper **不投影成任何边**(只投了 contradicts)→ 图层不可达。④ 的 `collectCognitiveEntities`(家族树收集器)除自身+测试外**零调用**(实际只 `countRetrievableAssetCategory` 被用,且它明确不是家族树口径)→ 纯死代码。

## 3. 中/低问题(去重后)

- **死 schema**:`promoted_from`/`corrects`/`evolves_into` 三边表零生产者;`memory_correction` 无节点表致 `corrects` 永远悬空(002_relations)。
- **双重存储**:relatedThemeIds/evidenceAnchors/contradictsPointIds 同时在 rest blob + 投影边,靠每次 persist 重投影维一致(脆弱)。
- **string 外键无级联**:turn.sessionId/note.sessionId/rag_chunk.sourceId/**memory.sourceId** 是裸 string;A5 EVENT 只覆盖 session→turn/note、material→rag_chunk,**memory.sourceId 源删无级联**(留悬空)。
- **② settled 永不复判**:reasoning.ts:46-50 把已成对永久排除,误判后 status 卡"被挑战中"无自动恢复。
- **sourceType 无 ASSERT**:memory/memory_candidate.sourceType 裸 string,枚举漂移无 DB 防线(material.sourceType 有 ASSERT,不一致)。
- **不可查的语义日期**:reviewAt(决策复盘日)/lastAccessedAt(recency)只在 rest、非 datetime → 无法 DB 侧排序过滤。
- **治理实体压 blob**:auditEvents/memoryCorrections/configVersions 等进 state_meta.rest 单行 → 审计流水不可按时间/实体查。
- **decisionKind ⟺ confirmationStatus 冗余**:两字段编码同一"是否用户确认",无约束保证同步。
- **③ search::rrf 少召回**:融合 limit=k 在 A4 门控前截断,deprecated/sensitive 占名额被删 → 返回少于 k 条(非泄漏,是少召回);融合非空但全被门控删剩 1 条时不补召(L 级)。
- **③ 长 topicHint BM25 噪声**:整句 topicHint 切 ngram 逐 token OR,长句几乎全表召回,BM25 退化为噪声(测试只覆盖单专名)。
- **三因子精排 relevance 静默归零**:embedding 缺失/维度不符时 cosine 返 0 → 排序退化为 recency 主导,无告警。
- **本地 embedding 冷启动联网**:首跑必须联网下载模型,与"完全离线"宣称在冷启动场景有缺口;单例首调失败会让首批并发 embed 同时退化。
- **③ 前端不可见**:混合检索 knowledgeFragments/ragChunks 只在 Chat 视图可见,采访引导界面不呈现(部分可触达)。
- **submitTurn 无 optimistic**:清空输入在 await 前,LLM 慢时用户"刚说的话消失"空窗(App.tsx:1158-1183)。
- **dev 端点不校验 sessionId 归属**:裸调下任意 id 可写 audit/追加轮次。
