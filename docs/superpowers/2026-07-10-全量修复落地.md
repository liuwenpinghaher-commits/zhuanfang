## 补审查发现与修复(B2/C1/C2 曾未经审查落库)

- **C1-Critical①**:reset/purge 绕过 outbox 生命周期——pending outbox 崩溃窗口后重开页面会复活"已清空"数据,冲突条可把 pre-reset 全量数据 PUT 回服务器;purge 后 localStorage outbox 仍存两份全量个人数据。修:reset/purge/import 三个整库替换入口统一走 `acceptAuthoritativeState`(清 outbox+对齐基线+清冲突)。
- **C1-Critical②**:网络失败的 reset 空态会被 outbox 在重连后静默 PUT——热态"看似清空"导致用户不再执行真正 reset,冷层(逐字稿/录音/索引)永久残留。修:该分支清 outbox 并把离线基线对齐到空态,行为与文案「恢复后请重新执行清空」一致。
- **C1-Important**:`synchronizeOfflineOutbox` 单 in-flight 队列互斥;共享重连探测 `scheduleReconnectProbe`(所有转离线点接线,4xx 停轮询);「采用服务器版本」丢弃前 `backupUnsyncedState`;outbox 写失败(配额)后重连改走合并不再采纳远端覆盖;死代码(`decideInitialSync` 等)删除、测试改钉真实路径;冲突按 path 去重。
- **B2-Important**:purge 部分失败(500+state+purgeReceipt)前端此前零消费(服务端已清、UI 仍显示全部数据)→ purgeData 仿 resetData 分流;import/purge 错误优先透出服务端中文 `body.error`(含非法条目清单摘要)。
- **C2-Important**:export `bundleDigest` 曾对 ~28MB 包再做排序深拷贝+二次序列化(违背 R4-5)→ 改对已序列化字符串单遍 FNV-1a;导入 422 中文错误曾被 UI 丢弃(并入上条修复)。
