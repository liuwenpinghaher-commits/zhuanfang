## 2. 正式发现 · P0

### P0-1 · CONFIRMED · 完整 export→import 后知识来源边丢失，图审计仍可 `ok:true`

- **位置**  
  - turn 仅热态投影：`packages/db/src/surreal/surreal-product-state-repository.ts`（`turnRecordsOf` / 约 1063+）  
  - 悬空边丢弃：`keepOnlyLiveTurnProvenance` / dangling 日志  
  - 审计：同文件约 913–945，`ok` **不**含 `danglingProvenanceCount`  
  - import：`apps/api/src/routes/state.ts` 恢复热态+冷 raw/audio，**无** cold-turn 图重建  
- **触发**：已完成会话降冷（`session.turns=[]`）后完整备份并导入空库  
- **失败**：`recallProvenanceTurns` 空；`surreal_dangling_provenance_dropped`；审计 `dangling>0` 仍 `ok:true`  
- **影响**：灾备后观点/记忆/主题无法溯源原话；跨会话预取证据链断裂；「完整备份可恢复」承诺不成立  
- **证据**：当前代码路径 CODE-CONFIRMED + 07-16 同 HEAD 实测 CONFIRMED  
- **修复方向**：import 时从 cold raw_material 重建 `turn` 节点再投影 `derived_from`；`ok` 在 `danglingProvenanceCount>0` 时为 false 或单独 fail 态；补 export→import→recall 回归钉

### P0-2 · CODE-CONFIRMED · 生产鉴权开启后官方 Docker SPA / 语音 WS 默认不可用

- **位置**  
  - `Dockerfile:11-14` 仅注入 `VITE_PRODUCT_API_BASE_URL`，**无** token  
  - `src/api/productApi.ts` 依赖 `VITE_PRODUCT_API_TOKEN`  
  - WS：`src/App.tsx:135-140`、`bailianWebsocket.ts:82`、TTS sink **不**附 `?token=`  
  - 服务端 WS 强制鉴权且支持 `?token=`：`realtime-voice.ts`  
- **触发**：`DEPLOYMENT_PROFILE=production` + 已设 `PRODUCT_API_TOKEN`（compose 强制）按官方镜像构建  
- **失败**：HTTP API 401；语音升级 401；服务「能起」但产品不可用，或运维误关鉴权  
- **影响**：生产部署闭环断裂  
- **修复方向**：同源 cookie/运行时 token bootstrap，或反向代理注入；浏览器 WS/媒体统一带 token；**禁止**把长期密钥烘焙进静态包当唯一方案（需文档化威胁模型）
