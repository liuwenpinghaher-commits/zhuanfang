## 0. 执行摘要

### 一句话

**跨会话上下文管道已经从「会中常假、中段常断」升级到「主路径能真召回、真回写、真失败」**；当前剩余问题不再是「有没有上下文」，而是：

1. **中段召回语义仍半冻结**（topic 图/BM25 绑开场，向量跟本轮）  
2. **card 与 guide 双通道叠注**（素材冻结 + 记忆重复）  
3. **默认语音场仍缺策略轨迹与助手权威落库**  
4. **HITL pending 在结束旅程上假「已记住」**  
5. **召回质量地板不全**（确认记忆无 relevance 闸、专访 RAG cosine 无最小分）

### 能力地图（CURRENT）

```text
CREATE  ── prefetch(topic) + guide/card 全量 ──► 开场上下文完整

  │
END     ── 记忆候选 pending ──► 用户须 HITL approve 才进跨会话 HNSW
```

## 2. 正式发现 · 仍 open 的 P1

### R-P1-01 · 中段 `topicHint` 冻结 → 图 / BM25 / 溯源与向量分叉

- **证据**：`interview-sessions.ts` 中途 prefetch 用 `session.guide.topicHint`；`prefetch-recall.ts:25-40` 图主题 `name === topicHint`、BM25 `queryText=topicHint`，HNSW 用本轮 embedding  
- **触发**：会话中途话题漂移（常见）  
- **影响**：向量记忆可能跟新话，主题资产/溯源原话/BM25 仍绑开场 → 「记得一点、图线索断」  
- **状态**：**open**（门禁修了「有没有 prefetch」，未修「prefetch 的查询语义」）

### R-P1-02 · C-P1-07 未完：card 素材半冻结 + 双通道叠注

- **证据**：中段只前插 `historyReferences`（`interview-sessions.ts` card 刷新）；`sourceHighlights` / `whyNow` / `potentialTension` 仍开场；`bailian.ts` 同时注入【可引用的历史原话】+【可引用的历史】+【联网素材】  
- **触发**：任意中段 turn / 语音刷新  
- **影响**：联网素材过时；同一批记忆双份进 prompt 挤占注意力；侧栏「开场历史」与「本轮记忆」两套叙事  
- **状态**：**partial**

### R-P1-03 · 默认语音场（Omni / LiveKit）strategyTrace 空 + 助手轮权威落库薄

- **证据**：`record-turn` 只写 `role/content/intent/timestamp`，无 strategy/referencedMemory；App 主路径常只 `record` 用户轮；`quality-report` 依赖 `strategyTrace` 算历史引用率  
- **触发**：默认语音（非级联 `/turns`）  
- **影响**：无引用气泡/技法；质量指标失真；归档/抽取可能缺助手侧内容  
- **状态**：**open**（文本/级联已好，默认语音仍断）

### R-P1-04 · HITL pending 在结束旅程上「假已记住」

- **证据**：finalize 候选默认 pending；HNSW/跨会话只吃 confirmed；`/end` 成功文案强调档案/笔记，不提「N 条待审才进跨会话召回」  
- **触发**：正常结束且不打开记忆治理页（常态）  
- **影响**：用户体感「系统没记住」；工程上是设计诚实 + UX 断环  
- **状态**：**open（产品 + UX）**

### R-P1-05 · `includePendingCandidatesInContext` 配置空转

- **证据**：pack 可收集 `pendingCandidates`；`collectRelevantMemories` / character prompt **不消费**；主站 Config 甚至无开关  
- **触发**：读配置/质检文案以为「待审可进上下文」  
- **影响**：**假配置成功**  
- **状态**：**open**

## 5. 根因（门禁后的新主因）

上一轮根因是「双速 + 空集合 + 写读不对称」。**那些主裂缝已补**。当前主因变成：

1. **查询语义双速**：embedding 跟本轮，图/BM25 跟开场 topic。  
2. **展示契约双通道**：card 开场快照 + guide 实时包，prompt 双读。  
3. **模态双速**：文本/级联有策略轨迹；默认语音无。  
4. **生命周期双速**：会话内可引用 confirmed；会话间被 HITL 截断且结束页不说。  
5. **质量地板不齐**：others 路径有 `score>0`，确认记忆与专访 RAG cosine 没有。

## 6. 建议下一批（只建议）

### 批次 E — 中段语义对齐（最高 ROI）

1. 中段 prefetch 的 `queryText` / 主题解析用 **本轮用户句或重解析 topic**，不要死绑开场 `topicHint`  
2. 或：图主题用 embedding 近邻主题，而不仅 `name ===`  

### 批次 F — 双通道收敛

1. character/voice prompt **只保留 guide 通道**，或 card 仅开场字段、不再叠注记忆  
2. 中段刷新 `sourceHighlights`（来自 guide rag/search）或停止注入冻结素材  

### 批次 G — 语音权威态

1. Omni/LiveKit 助手转写走权威 `record-turn`（含 strategy 可选）  
2. 或语音回合结束后补写 strategyTrace / referencedMemory  
3. LiveKit pre_signals 失败对齐 Omni notice  

### 批次 H — 召回地板 + 可观测

1. `collectRelevantMemories`：`relevance > 0`（或最小三因子阈值）  
2. 专访 `topKByCosine` 对齐 chat `score>0`  
3. import/reindex/approve 把 embedding 覆盖率/warning 传到 UI  

### 批次 I — HITL 产品诚实

1. `/end` 文案与 notice：`pendingCandidateCount` + 引导治理  
2. 要么真正消费 `includePendingCandidatesInContext`，要么删除/改文案
