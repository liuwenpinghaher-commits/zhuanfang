# 专访 1.0 · 专家团：上下文深度分析报告

> **日期**：2026-07-23  
> **模式**：Review only（不改代码）  
> **问题域**：「整个上下文」= 专访/语音如何**组装、注入、刷新、消费、归档后再召回**长期与会中上下文  
> **方法**：Lead + 2 路并行只读审查（专访注入链 / 记忆·图·RAG 链）+ 主控对关键路径 file:line 交叉核验  

---

## 0. 执行摘要

### 一句话

系统已经具备 **真实的跨会话上下文管道**（建会话时 native 预召回 + guide/card 注入 LLM prompt），**不是**「只在 UI 画历史引用」的空壳；但存在 **多条分叉路径、冻结快照、空数组误缩池、敏感旁路、UI 与 prompt 不一致** 等问题，导致「看起来有记忆」和「模型真的带着正确记忆」经常不对齐。

### 能力地图（先读这段）

```text
[ProductState: 记忆/主题/资产/简报/导入资料]
        │
        ├─ CREATE 会话
        │    embed(topic) + prefetchRecall(图主题/HNSW记忆/溯源/RAG)
        │    → createSessionDraft → session.card（冻结）+ session.guide
        │
        ├─ 文本 /turns（每轮）
        │    embed(user) → buildInterviewGuide(⚠ 无 prefetchRecall)
        │    → 持久化 guide → character system prompt(card+guide)
        │    → 近 8 轮对话
        │
        ├─ Omni 语音
        │    record-turn（仅 turns）
        │    voice-instructions 刷新 guide（⚠ 无 prefetch、⚠ 不回写 session）
        │
        ├─ LiveKit
        │    agent-context（✓ 可 prefetch）但仍 ⚠ 不回写 session.guide
        │
        └─ /end
             记忆候选 pending → 用户 approve(+embed?) → 下次 create 才进向量召回
```

### 本轮分级（开放）

| 级 | 条数 | 主题 |
|---|---|---|
| **P1** | **8** | 敏感旁路、中途无 native 召回、UI/trace 不一致、空 hits 缩池、approve 无向量、card 冻结、HITL 闭环默认断 |
| **P2** | **约 10** | 无关记忆保底、tracked 简报过宽、citation 分裂、dangling 静默、主题归属失败、token 只按条数 cap 等 |
| **P3** | **约 4** | 配置态标注、pre_signals 静默、reindex 延迟等 |

### 与「系统有没有上下文」的关系

| 问题 | 答案 |
|---|---|
| 有没有跨会话记忆进模型？ | **有**——`guide.relevantMemories` / `historyReferences` 进 character 与 voice instructions |
| 是不是全程一致？ | **否**——开场强、文本中段弱、语音状态不回写、UI 常显示开场冻结引用 |
| 最大风险类型 | **漏记**（空 hits、无向量）+ **污染**（零相关仍取 3 条、tracked 简报）+ **假透明**（UI ≠ prompt ≠ strategyTrace） |

## 1. 正式发现 · P1

### C-P1-01 · 敏感确认记忆可经 `historyReferences` 绕过安全门控

- **file**：`src/domain/context-pack.ts:934-943`（`collectConfirmedMemoryTexts` 只滤 `confirmed`，**不过滤 sensitive**）；对比 `328-331` 的 `isModelSafeMemoryRecord`
- **注入**：`historyReferences` 进 card → 文本 `bailian.ts:925-928`、语音 `voice-instructions.ts`
- **触发**：存在 `sensitivity=sensitive` 的 confirmed 记忆，且默认 `includeSensitiveMemoriesInContext=false`
- **影响**：敏感内容仍可进模型「可引用的历史原话」与侧栏历史引用
- **证据**：CODE-CONFIRMED

### C-P1-02 · 文本 `/turns` 与 Omni `voice-instructions` 每轮不走 `prefetchRecall`

- **file**：建会话 `interview-sessions.ts:122-131` 有 prefetch；每轮 `209-216` / voice-instructions `566-572` **无**；LiveKit `realtime-voice.ts:413-429` **有**
- **触发**：surreal 权威 + 会话进行中话题漂移
- **影响**：图主题资产、HNSW 粗召、provenance 证据原话、原生 RAG 只在开场完整；中段退化为全库 embedding/子串精排
- **证据**：CODE-CONFIRMED

### C-P1-03 · UI「历史引用」与模型上下文 / strategyTrace 不一致

- **侧栏**：`InterviewView` 读冻结的 `session.card.historyReferences`
- **模型**：每轮刷新的 `guide.relevantMemories` + card 历史（bailian 双通道）
- **气泡引用**：`receiveTurn` 未传 `referencedMemory` → `turn-builder` 回落 `card.historyReferences[0]`
- **影响**：用户以为引用 A，策略/prompt 可能在用 B；语音 `record-turn` 甚至不写 strategyTrace
- **证据**：CODE-CONFIRMED（与 07-16 真人验收「可见引用失真」同构）

### C-P1-04 · 语音刷新召回不回写 `session.guide`（状态与模型分叉）

- **file**：Omni `interview-sessions.ts` voice-instructions 注释 read-only；LiveKit agent-context 只返回指令
- **对比**：文本 turn 会把刷新后的 guide 持久化
- **影响**：模型可能已用新记忆；归档/质量/UI 仍看开场 guide
- **证据**：CODE-CONFIRMED

### C-P1-05 · 空 `memoryHits: []` 误缩长期记忆池

- **file**：`prefetch-recall.ts:75` 空数组仍注入；`context-pack.ts:341-347` 把 truthy 的 `[]` 当「有原生召回」
- **触发**：HNSW 无命中 / 确认记忆全无 embedding
- **影响**：本应回落全量 `memoryRecords` 的路径被绕过 → **【可引用的历史】可整段消失**
- **证据**：CODE-CONFIRMED；缺 `memoryHits:[]` 回归钉

### C-P1-06 · 记忆 approve 嵌入失败仍确认成功（无向量 confirmed）

- **file**：`memory-candidates.ts:109-119` embed 失败则无 embedding 仍 approve
- **影响**：HNSW 永远看不见该记忆；叠加 C-P1-05 可导致原生路径「长期记忆全空」
- **对比**：建会话/chat embed 失败已 502
- **证据**：CODE-CONFIRMED

### C-P1-07 · `session.card` 开场冻结，中途历史原话/联网素材不跟话题漂移

- **file**：prompt 读 `session.card.historyReferences` / `sourceHighlights`（`bailian.ts:923-937`）；turn 只更新 guide
- **影响**：【可引用的历史原话】与【联网素材】卡在开场 topic；中途真正相关的 provenance 进不了 character 的 card 通道
- **证据**：CODE-CONFIRMED

### C-P1-08 · finalize 后长期记忆默认卡在 pending（HITL 闭环）

- **file**：抽取 → pending candidates；默认 `includePendingCandidatesInContext: false`；HNSW 仅 confirmed
- **触发**：归档后用户不审候选（常态）
- **影响**：产品若预期「刚聊完就记住」，表现为跨会话失忆；设计若坚持 HITL，则缺「N 条待审、暂不可召回」显性状态
- **证据**：CODE-CONFIRMED（产品预期问题 + 工程缺口）

## 5. 根因归类（比清单更重要）

1. **双速上下文**：Create/Agent 完整，Turn/Omni 缩水 → 中段「失忆感」。  
2. **双份展示契约**：card 冻结 vs guide 刷新 vs strategyTrace → 假透明。  
3. **空集合语义错误**：`memoryHits: []` 被当「有原生召回」→ 池被清空。  
4. **写路径与读路径不对称**：approve 可无向量；读路径却高度依赖 HNSW。  
5. **预算是条数不是 token**：缺统一优先级（护栏 > 边界 > 相关记忆 > 素材）。

## 6. 建议修复批次（只建议）

### 批次 A — 正确性 / 安全（先做）

1. `collectConfirmedMemoryTexts` 对齐 `isModelSafeMemoryRecord`（C-P1-01）  
2. `memoryHits` 仅 `length > 0` 时缩池；prefetch 空数组不注入（C-P1-05）  
3. approve 无 embedding → 暴露字段或 4xx/告警，禁止静默「不可向量召回的 confirmed」（C-P1-06）

### 批次 B — 一致性

1. `/turns` 与 voice-instructions 对齐 prefetchRecall（C-P1-02）  
2. 语音刷新可选回写 `session.guide` 或明确「模型上下文不进权威态」（C-P1-04）  
3. UI 展示 `guide.relevantMemories`；turn 写入真实 `referencedMemory`（C-P1-03）  
4. 每轮刷新 card 的 history/source 或并入 guide 注入（C-P1-07）

### 批次 C — 召回质量

1. 去掉零相关记忆保底 3 条；tracked brief 强制主题重叠  
2. rag citation 对齐 chat；provenance 覆盖 memoryHits  
3. token 级预算 + 护栏优先  

### 批次 D — 产品闭环

1. HITL 待审显性：「有 N 条记忆尚未进入跨会话召回」  
2. LiveKit pre_signals 失败可见
