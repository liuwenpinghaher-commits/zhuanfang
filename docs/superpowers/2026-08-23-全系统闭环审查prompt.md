## Prompt 正文（从这里开始复制）

你要对 **专访（zhuanfang）** 当前主仓做一次全系统闭环审查。产品是语音专访式认知工具：React 前端 + Fastify Product API + 域层同步纯函数 + SurrealDB（R7 仅 `memory|surreal`）+ 冷层（raw material / audio / knowledge index）+ LLM/语音供应商。

目标不是再写一篇功能说明书，而是用当前代码、当前接线、当前 demo 冒烟，回答：

1. **接线**：每个闭环从 UI → `productApi.client` → 路由 → 能力注入 → 域函数 → 持久层 → 下游消费者，是否全通；有没有「API 有、App 不调」「装配漏传」「capabilities 撒谎」「死表/死字段」。
2. **统一**：该共用一份真源的，是否真的共用（预算、写门、召回、语音栈、索引、主题回访、错误语义）。
3. **闭环**：用户能从入口走到出口，产物会被下一环消费；失败可见、可重试、不假成功。
4. **断点**：按钮/路由/状态机/后台任务在哪一跳停住、吞错、或只写不读。
5. **爆炸半径**：这条环写脏之后，会污染哪些下游（turns → 笔记/记忆/资产/RAG/播客/复盘）。半径必须用「谁生产、谁存储、谁消费、谁删除」账本证明，不能凭印象。

### 1. 发现准入

每条进入最终报告的发现必须有：

- `file:line` 或命令/HTTP 输出
- 触发条件（配置、输入、状态、时序）
- 失败场景（用户或下游会看见什么）
- 影响面（丢数据、假成功、不可达、隐私、静默腐化、维护分叉）
- 复现方式，或写明只能静态推理
- 反驳：先写「为什么可能不是问题」，再写为何仍成立或降级为疑点

证据等级：`CONFIRMED`（已跑通） / `CODE-CONFIRMED`（路径闭合未跑） / `PLAUSIBLE`（推理强，缺运行） / `REGRESSION-SEED`（旧报告未复核，不得当最终发现）。

严重度：

- `P0`：确定性丢数据、隐私泄漏、核心写入楔死、认证绕过、主旅程不可用
- `P1`：高概率假成功 / 核心能力生产不可达 / 长期静默腐化
- `P2`：业务语义错、状态机断环、降级无信号、运维恢复风险
- `P3`：测试盲区、可维护性、文案/可观测性小缺口

### 2. 每个模块必须交的六张答卷（强制）

无论审哪一条环，输出必须按这六块，缺一块就不算审完：

**A. 接线账**  
从用户动作到落库到被下一环读到。每一跳标注：`有调用` / `有路由无调用` / `有路由装配漏依赖` / `有前端无后端` / `仅测试可达` / `有意关闭`。  
最少追：UI 入口 → `src/api/productApi.client.ts` 方法 → `apps/api/src/routes/*` → `apps/api/src/server.ts` 注入（`llmBudget` / `writeGate` / embedding / 冷库） → 域函数 → 仓库（热态 / 冷层 / 图边 / 向量） → 下游消费者（专访召回、chat、主题、播客、复盘、导出）。

**B. 统一性**  
列出本环与相邻环是否共用真源。重点对照：

- 三套语音（cascade / Omni realtime / LiveKit）的 turns 权威、打断、strategyTrace、预算、录音
- 两套知识（`state.ragChunks` vs `knowledgeIndexRepository`）
- 预算桶（`sharedBudget` / `SYSTEM_BUDGET_KEYS`）是否覆盖本环 LLM/embed
- 写门（全局写锁 vs `writeGate` CAS）是否同一套语义
- 主题回访是否真的把 `topicHint` / `relatedThemeIds` 带进建场
- 错误码：422/409/429/5xx 在 client 是否被吞成成功

**C. 闭环**  
用用户能听懂的一句话写「打开产品，这条环从哪进、中间发生哪一件事、最后留下什么」。然后判定：留下的东西有没有被下一环读到。只写不读 = 断环。只读无写 = 死展示。

**D. 断点清单**  
状态机每个合法跳转：入口谁保证前置、失败用户看见什么、双击/重入会怎样、中途杀进程会怎样、降级后还能不能走完。点名具体按钮、路由、后台任务。

**E. 爆炸半径账本**（必须填表，禁止空谈）

| 实体/字段 | 谁生产 | 存在哪 | 谁消费 | 谁删除/过期 | 写脏之后打中谁 | 半径评级（本环/跨环/全库） |
|---|---|---|---|---|---|---|
| … | … | … | … | … | … | … |

半径评级规则：

- **本环**：只影响当前页展示
- **跨环**：会进入另一条用户旅程（例如 turns 脏 → finalize 笔记脏 → 记忆/RAG/播客）
- **全库**：会经 PUT `/api/state`、import、rebuild、图投影污染权威态

若某字段只写不读、或图边无消费者，标 `死数据` 或 `预留`，并给 blast-radius 证据（codegraph 或 grep 消费点）。

**F. 结论一句**  
`闭环成立` / `半接线` / `假闭环` / `有意未开`。假闭环 = UI 说做成了，下游其实没吃到。

### 5. 各模块独立审查段

下面每一段都可以单独复制给一个 agent。agent 必须只审本段，但爆炸半径要追到下游（读代码，不改范围外的结论）。共用纪律见 §0–§2。

------------------------------------------------------------
#### 【独立段 M01】登录与数据隔离

**人话闭环：** 打开站点要登录；登进去只能看见自己的专访和资产；登出后别人不能接着用。

**代码锚点：** `apps/api/src/auth.ts` · `apps/api/src/auth/` · `src/features/auth/LoginPage.tsx` · `docs/L1-AUTH-SESSION-PLAN.md` · `docs/runbooks/user-scoped-stores.md` · USER_SCOPED Proxy（`server.ts`）

**必追：**

1. 生产 `DEPLOYMENT_PROFILE=production` 无 token 是否拒启。
2. 哪些路由 auth 豁免（health、静态、WS、媒体 `?token=`、LiveKit agent）。豁免是否 fail-closed。
3. Origin / CSRF 在本地、反代、公网 demo 是否一致。
4. USER_SCOPED 是否把治理能力（hybrid/governance/graph audit）在装饰后丢掉（历史 spread+Proxy 坑，需用当前代码复核）。
5. 多用户数据目录是否隔离；导出/备份会不会带上别人的仓。

**统一：** 前端带 token、原生 `<audio src>` 的 query token、LiveKit agent Bearer、WS 鉴权是否同一套语义。

**闭环/断点：** 登录失败、过期、改密码/轮换密钥（见 `docs/plans/2026-08-21-key-rotation-waiver.md` 是否仍适用）、cookie 与 Bearer 混用。

**爆炸半径：** 鉴权旁路 = 全库；隔离失败 = 跨用户隐私 P0。

**完成句：** 外人进不来，两人不相串。

------------------------------------------------------------
#### 【独立段 M02】今日访谈台

**人话闭环：** 打开首页，未完成的场能继续；系统建议的下一场能带着主题开；误开的空场能扔掉；不会默默开出两场空壳。

**代码锚点：** `src/features/home/HomeView.tsx` · `src/domain/revisit-queue.ts` · `src/domain/lifecycle.ts` `discardEmptyActiveInterviewSession` · `src/hooks/useInterviewSessionActions.ts` · `POST /api/interview-sessions` · `POST .../discard`

**必追：**

1. 「继续」是否走已有 session，而不是再 create。
2. 「按建议开场」是否把 `topicHint`、`relatedThemeIds`、可选 `searchBriefId` 传到 create。
3. 空场 discard 的前置（无用户轮）前后端是否一致；UI 是否真调用 discard。
4. `startingRef` 防重入是否覆盖按钮、回车、语音入口。
5. 首页卡片数据是否只读本地态，服务端 active session 不同步时谁赢。

**统一：** `resolveInterviewTopicHint`、卡片 `buildInterviewCard`、真正 create payload 三处 topic 是否同一来源。

**爆炸半径：** 开场 topic 错 → 整场召回偏题（跨环：记忆、调研、主题）。双 create → 空壳污染会话列表和今日台。

------------------------------------------------------------
#### 【独立段 M03】文字专访

**人话闭环：** 打字提问，主持人下一问回来；放慢/换角度/摘要/不保存等控制键改的是这一场；中途失败能看见，不会丢你刚说的话。

**代码锚点：** `src/features/interview/InterviewView.tsx` · `useInterviewSessionActions.ts` · `POST /turns` · `POST /turns/stream` · `POST /turns/cancel` · `POST /control` · `src/domain/engine.ts` · `src/domain/turn-builder.ts` · `src/domain/strategy.ts`

**必追：**

1. 文本主路径是 `/turns` 还是 `/turns/stream`；前端实际走哪条；cancel 能否取消服务端落库。
2. control 对已 offload / 已 completed 是否拦截。
3. `/turns` 是否持写锁做长 LLM；失败是否回滚、用户输入是否stash。
4. playbook / 策略 / guidance 是否进入本场 prompt，而不是只写 audit。
5. `do-not-save` 从控制键到 session 标记是否贯穿到 M05。

**统一：** 文本 `/turns` 与 cascade 流式 `/turns/stream`、Omni `record-turn` 是否写入同一 `session.turns` 权威。

**爆炸半径：** turns 是全下游之源。丢轮/幽灵轮 = 笔记、记忆、资产、冷层、质量分全部脏。半径 = **全库**。

------------------------------------------------------------
#### 【独立段 M04】语音专访

**人话闭环：** 点语音后主持人先开口；底下的字跟着你说；他正在说的那句默认说完；你真抢话他才停；停的半句留在场里；录音能对上轮次。
