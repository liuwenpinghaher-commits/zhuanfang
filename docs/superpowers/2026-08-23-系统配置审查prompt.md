## Prompt 正文（从这里开始复制）

你要对 **专访（zhuanfang）的「系统配置」模块** 做一次彻底审查。

用户体感是：这一页「感觉全是问题」。不要先辩解产品设计，先用当前代码证明：哪些格子拧了下一场真会变，哪些只是样子，哪些拧了会把整站弄坏。

产品是语音专访式认知工具。系统配置页在 `src/features/config/ConfigView.tsx`，导航是「系统 → 系统配置」，分两个页签：

- **状态**：能力灯、引擎摘要、生成物计数、「清理重复生成物」
- **参数**：上半是服务端 env（密钥/模型/端点），下半是产品策略（`ProductState.systemConfig`），中间夹着声音复刻

这一页不是普通表单。它同时管三件不同的事：

1. **机器钥匙**：写 `.env` / 进程环境，刷新供应商客户端（`PATCH /api/system/config`）
2. **这本书的规矩**：写进用户的产品状态，走 autosave（搜索默认、语音档、记忆开关、访谈节奏）
3. **健康灯**：`GET /api/system/capabilities` 声称现在哪项能用

审查目标不是再写说明书，而是回答：

1. 拧了这颗螺丝，下一场专访 / 下一次搜索 / 下一次记忆召回，是不是真的按新规矩走？
2. 灯绿了是不是真能用？灯红了页面是不是还允许选它？
3. 两套配置（env vs 产品策略）有没有同名、互相覆盖、保存成功但下游读另一份？
4. 哪些格子是死的（OpenAI TTS、配置版本回滚、模型名字段）？
5. 在生产站上改密钥/存储路径，会不会把整站写死或把秘密暴露在浏览器？

### 0. 纪律

1. **当前代码是唯一真相。** README、历史审查、设计稿、注释只能当线索。
2. **旧结论必须重判。** 至少扫过但不得照抄：
   - `docs/superpowers/2026-08-23-全系统闭环审查prompt.md` 的 M17
   - `docs/superpowers/CURRENT-开放清单.md`
   - `docs/plans/2026-08-12-zhuanfang-incomplete-wiring-optimal.md`
   - `apps/api/src/e2e/system-module-journey.test.ts`
3. **测试绿 ≠ 用户能用。** capabilities 单测、ConfigView 渲染测不能证明生产拧螺丝有效。
4. **fail-soft 不是 bug。** 无信号、假成功、拧了没变、灯撒谎才是 bug。
5. **不泄露 secret。** 不打印 `.env.production.local`、token、cookie。冒烟时只看状态码、是否 masked、是否 401/422。
6. **只读审查。** 不改业务代码。demo 上不要真改密钥、不要改 `PRODUCT_STATE_DB_PATH`、不要 reset/purge。需要验证「保存产品策略」时，只用无害字段（如时效窗口）或只静态追调用链。
7. **本机资源极紧。** 禁止 `npm ci`、全量 vitest、Playwright、本机 Surreal。静态读代码 + 对已部署 demo 的只读/廉价冒烟。
8. **有意 opt-in 先核实再打。** 后台定时调研默认关、敏感记忆默认不进上下文、cascade 是默认语音。默认关且灯/文案一致 → `有意关闭`，不是缺陷。

### 1. 发现准入

每条最终发现必须有：

- `file:line` 或 HTTP 输出
- 用户拧的是哪一格
- 保存走哪条写路径
- 下游谁读（点名函数，不要说「应该会读」）
- 失败时用户看见什么（成功 toast / 无变化 / 灯仍绿）
- 反驳：为什么可能不是问题，为何仍成立或降级为疑点

证据等级：`CONFIRMED` / `CODE-CONFIRMED` / `PLAUSIBLE` / `REGRESSION-SEED`。

严重度：

- `P0`：生产可被页面改掉密钥/库路径导致整站不可用；能力灯掩盖鉴权失败；配置写脏导致跨用户串数据
- `P1`：保存显示成功但下游仍读旧值；选了不可用的 provider 仍当可用；秘密回显
- `P2`：装饰控件、双真源、版本历史只写不读、改完要重启却不说
- `P3`：文案、测试盲区、页内重复入口

### 2. 怎么审（方法，不要按 UI 分区扫）

**先建「螺丝 → 下游」账本，再进页面。** 禁止只读 ConfigView 就下结论。

对每一颗螺丝问四句：

1. 页面上有没有这个格子？只读还是可改？
2. 点保存，写到哪？env 文件 / `process.env` / `ProductState.systemConfig` / 只 setState 本地 / 其实没写？
3. 运行时谁读？搜索、建场、turns、cascade、Omni、LiveKit、播客 TTS、记忆召回、chat、调研调度，是不是同一份？
4. 读不到或读另一份时，用户怎么发现？灯？顶栏？静默沿用旧值？

结论只许四选一：`拧了会变` / `拧了要重启才变` / `拧了是样子` / `有意未开`。

### 3. 必须交的六张答卷

#### A. 接线账

最少追这几条，缺一条不算审完：

**A1. 服务端 env**

UI「保存服务端配置」→ `App.saveRuntimeConfig` → `productApiClient.updateSystemConfig` → `PATCH /api/system/config` → `writeEnvFileUpdates` + 改 `options.env`/`process.env` → `refreshProviderClients` → 再 `GET /api/system/capabilities`。

必查：

- 哪些 key 在 `runtimeSettingDefinitions` 里，但保存后 `refreshProviderClients` 并不重建对应客户端
- 标了 `restartRequired` 的（至少 `PRODUCT_STATE_DB_PATH`）保存成功后文案是否说谎
- 生产 profile 是否允许浏览器改密钥；env 文件路径是否回给前端
- 密钥字段留空=保持不变，是否真的不会把 key 清掉；必填密钥清空是否 422
- 写入的是绑定的 `.env.production.local` 还是进程内一份，容器重启后还在不在

**A2. 产品策略**

UI「保存产品策略」→ `App.saveProductConfig` → 直接 `setProductState({ systemConfig })` → 靠 autosave `PUT /api/state`。

必查：

- 有没有走 `withSystemConfigVersion`（域层有版本/diff/回滚快照）。若没走：`configVersions` 是死数据还是只有语料补丁在写？
- 保存成功 toast 是否在服务端确认之前就弹出
- 离线/409 时，页面上的新策略会不会被权威态打回，用户知不知道
- `setPodcastVoice` 等旁路状态是否和 `systemConfig.voice` 分叉

**A3. 能力灯**

`GET /api/system/capabilities` 的 `status`/`active`/`detail`/`requiredEnv` 分别怎么算。`active` 若来自 `state.systemConfig`，而 `status` 来自「有没有 client」，两者打架时 UI 怎么表现。

**A4. 声音复刻**

配置页上传/删除音色 → `/api/realtime-voice/voices` → 是否写进「默认访谈声音」下拉；删掉正在用的音色，下一场用什么。

**A5. 生成物清理**

「清理重复生成物」→ 哪个域函数 → 是否真删搜索简报/播客/语料，会不会误伤用户手写资产。

#### C. 闭环（人话）

用用户能听懂的话写三条，每条判定成不成立：

1. 我换了默认搜索，下一份简报是不是新这家出的。
2. 我关掉「敏感记忆进上下文」，下一场主持人是不是真的不再提起那些。
3. 我把实时模式改成级联/百炼直通/LiveKit，下一场开口是不是真换了路。

只改灯不改路 = 假闭环。只改路不改灯 = 危险闭环。

#### D. 断点清单

至少覆盖：

- 保存服务端配置：空提交、非法数字、清必填密钥、env 文件不可写、refresh 抛错
- 保存产品策略：连点、切页未保存、autosave 409、未登录
- 能力灯加载失败时参数页是否仍允许选红灯 provider
- 改 `realtimeMode` 时正在进行的专访会不会中途换栈
- 调研开关改完要等下一个调度周期：文案是否够，调度器是否真读这个字段

### 4. 必须逐格勾销的产品策略字段

`SystemConfig` 在 `src/domain/types.ts`。**每个字段**填：

`页面有无` · `保存路径` · `运行时消费者 file:line` · `三套语音是否都读` · `结论`

字段清单（不准漏）：

- `version`
- `providers`
- `search.activeProvider` / `recencyDays` / `maxSources` / `allowWebInInterview`
- `voice.ttsProvider` / `defaultVoice` / `podcastVoice` / `podcastGuestVoice` / `podcastFormat` / `realtimeMode` / `minBargeInMs` / `endpointingMode` / `useLayer2Endpoint` / `halfDuplexFallback`
- `models.planningModel` / `interviewModel` / `synthesisModel`
- `interview.playbookVersion` / `launchMode` / `silenceHoldMs` / `maxFollowUpDepth` / `guidanceEnabled` / `guidanceFrequency` / `maxGuidancePerTurn` / `minGuidanceIntervalMs` / `challengeBudgetPerSession`
- `memory.includeSensitiveMemoriesInContext` / `includePendingCandidatesInContext` / `externalMaterialMemoryPolicy` / `minRecallScore`
- `research.autoScheduleEnabled` / `scheduleIntervalMin`

特别怀疑（允许证伪，不许跳过）：

1. `saveProductConfig` 不走 `withSystemConfigVersion`，版本历史对用户改策略是死的；语料补丁反而会写版本。
2. `ttsProvider` 的 openai / elevenlabs 没有客户端，选了也还是百炼或静默降级。
3. `models.*` 状态页在展示，参数页不能改，真正模型名在 env。
4. `minBargeInMs` / `endpointingMode` 等 cascade 旋钮在类型里、配置页没有，实际读的是别的 settings。
5. `externalMaterialMemoryPolicy` 配置页没有。
6. 播客音色在 env 和产品策略和播客工作台三处可改。
7. 能力灯 `active` 跟选中的 provider 不是同一时刻刷新。
8. 生产站参数页能改密钥，等于把运维面暴露给已登录用户。
