# 专访 · 认知资产彻底审查 Prompt（2026-08-23）

> **用法**：开新 session，把「Prompt 正文」整段交给审查者。只审导航里的「认知资产」及其爆炸半径，不要扩成全系统审查。  
> **仓库**：`/home/admin/projects/zhuanfang`  
> **验收环境**：已部署 demo `https://zhuanfang.qing.blue`（只冒烟已部署栈）。  
> **本文性质**：审查指令。不改代码、不宣称修好、不把旧报告当现状。  
> **方法同源**：与「系统配置审查」「访谈工作台审查」同一套逻辑——先建账本，再进页面。配置页问的是「拧了下一场变没变」；工作台问的是「点了这场书里真发生了没有」；认知资产问的是「点了这条，书里改没改、下一场用不用」。

## Prompt 正文（从这里开始复制）

你要对 **专访（zhuanfang）的「认知资产」** 做一次彻底审查。

侧栏这一组有七页：

- **双轨笔记**（`notes`）`src/features/notes/NotesView.tsx`
- **素材库**（`material`）`src/features/material/MaterialLibraryView.tsx`
- **资产对话**（`asset-chat`）`src/features/chat/AssetChatView.tsx`
- **我的资产**（`my-assets`）`src/features/my-assets/MyAssetsView.tsx`（内嵌 `AssetsView`）
- **外部调研**（`search`）`src/features/search/SearchIntelligenceView.tsx`
- **记忆**（`memory`）`src/features/memory/MemoryGovernanceView.tsx`
- **播客**（`podcast`）`src/features/podcast/PodcastStudioView.tsx`

产品是语音专访式认知工具。这七页不是七本说明书，是同一座库：谈完留下的东西，人要能读、能改、能忘掉、能带回下一场。用户体感如果「全是问题」，通常是：状态拧了、确认点了、导入成功了，下一场专访和对话却还拿旧的、拿空的、或拿编的。

不要先辩解产品设计。先用当前代码证明：哪个按钮点下去，这条资产在书里真变了，而且下一场/对话/播客真认这份；哪个只是样子；哪个点了会把别的场、别的线的东西一起写脏或删掉。

这一组同时管六件不同的事，必须分开记账，不许揉成「资产模块都有」：

1. **笔记**：能读这场；能跳原文/主题/档案；忘掉这场时，可选连带只属于这场的产出，不许误伤合并过的东西
2. **四件套**：观点、问题、决策、知识债能改状态、标重要、确认决策、带回下一场
3. **记忆**：待审要点头才进长期；改了字再批，下一场召回的是新字；矛盾能裁决
4. **素材**：贴进来能切块；该审的去记忆页；专访和对话真能问到这份资料
5. **资产对话**：对着自己的书提问，引用能点回去；答不上来要拒绝，不许编
6. **调研与播客**：简报能带进专访；笔记/主题能出稿，确认后再出声

审查目标不是再写说明书，而是回答：

1. 点了「确认 / 改状态 / 忘掉 / 带入专访」，刷新后书里是不是这份？下一场是不是用这份？
2. 失败时用户看见什么？装成功、吞掉、还是能重试？
3. 本地改一笔 + 整本保存，和专用确认接口，会不会各写各的、谁赢谁输用户看不见？
4. 笔记、资产库、记忆、对话、调研、播客，是不是认同一条 id？还是各展览各的？
5. 忘掉、合并、确认，会不会把别的场共用的观点/记忆一起干掉？

### 0. 纪律

1. **当前代码是唯一真相。** README、历史审查、设计稿、注释只能当线索。
2. **旧结论必须重判。** 至少扫过但不得照抄：
   - `docs/superpowers/2026-08-23-全系统闭环审查prompt.md` 的 M06 / M07 / M09 / M10 / M11 / M12 / M14
   - `docs/superpowers/2026-08-23-访谈工作台审查报告.md`（结束是资产工厂；笔记挂主题线刚修过）
   - `docs/superpowers/CURRENT-开放清单.md`
   - `apps/api/src/routes/assets.ts` 头注释（声称只留决策确认走服务端）
   - `src/domain/lifecycle.ts` 的忘掉笔记
3. **测试绿 ≠ 用户能用。** 域测绕过 App、假 LLM、不经 autosave，不能证明 demo 上改完下一场认。
4. **fail-soft 不是 bug。** 无信号、假成功、点了没写、灯撒谎才是 bug。
5. **不泄露 secret。** 不打印 token、cookie、`.env.production.local`。
6. **只读审查。** 不改业务代码。demo 上不要 reset/purge、不要忘掉别人的笔记、不要批准/拒绝别人的记忆。需要验证写路径时，优先静态追调用链；能用 GET/health/未登录 401 就不要写。
7. **本机资源极紧。** 禁止 `npm ci`、全量 vitest、Playwright、本机 Surreal。静态读代码 + 对已部署 demo 的只读/廉价冒烟。
8. **有意 opt-in 先核实再打。** 敏感记忆默认不进上下文；调研自动盯梢默认关；播客默认先确认再出声。默认关且文案一致 → `有意关闭`，不是缺陷。
9. **合并过的东西默认受保护。** 忘掉一场笔记，跨场复用的观点/已确认记忆不得当这场私产删掉。可选连带必须是用户勾了、而且只删「只属于这场」的。

### 1. 发现准入

每条最终发现必须有：

- `file:line` 或 HTTP 输出
- 用户点的是哪个按钮/键
- 走哪条写路径（client 方法、路由、域函数、整本 PUT、冷层）
- 下游谁读（点名函数，不要说「应该会读」）：下一场 prompt、回访队列、资产对话、播客稿、雷达
- 失败时用户看见什么（toast / 列表还在 / 装已确认）
- 反驳：为什么可能不是问题，为何仍成立或降级为疑点

证据等级：`CONFIRMED` / `CODE-CONFIRMED` / `PLAUSIBLE` / `REGRESSION-SEED`。

严重度：

- `P0`：忘掉一场误删别人场共用的观点/记忆；对话对着空库编故事还像引了书；未登录能改资产
- `P1`：确认/改状态显示成功但下一场仍用旧值；引用点回去是空页；导入成功但问不到
- `P2`：双写路径（本地改 vs 专用接口）谁赢不说；带入专访开错模式；页是展览下游不读
- `P3`：文案、测试盲区、页内重复入口

### 2. 怎么审（方法，不要按七页分区扫完就算）

**先建「按钮 → 书里这条变了什么、下一场谁读」账本，再进页面。** 禁止只读 MyAssetsView/NotesView 就下结论。

对每一个入口问四句：

1. 页面上有没有这个按钮？可点还是灰的？
2. 点下去写到哪？专用 `POST /api/assets/...` / `/api/notes/:id/forget` / `/api/memory-candidates/:id/approve` / 只 `setProductState` 等整本 PUT / 其实没写？
3. 运行时谁读？下一场 `buildInterviewGuide` / 回访队列 / 资产对话 / 播客稿 / 雷达，是不是同一条 id、同一份字？
4. 没写上或写错场时，用户怎么发现？红条？刷新还原？静默沿用旧值？

结论只许四选一：`点了会发生` / `点了要等下次保存/下一场才发生` / `点了是样子` / `有意未开`。

配置页审的是格子；工作台审的是一场活；这里审的是库。不要把「四种资产筛选项都在」当成闭环。

### 3. 必须交的六张答卷

#### A. 接线账

最少追这些，缺一条不算审完：

**A1. 双轨笔记**

打开笔记 → 读这场摘要/原话/学到的；跳原文、主题、档案、播客；把笔记里的问题存成资产；忘掉这场。

必查：

- 热态 turns 已降冷时，原文是不是改读 raw-material，而不是对着空数组装没说过
- 音频能不能播（带 token 的 url 与 blob 两条）
- 「用此问题开场」是否把题和主题线带进下一场
- 忘掉：默认只拿掉这场记录；勾了「只属于这场的产出 / 已确认记忆」才连带；合并过的观点、跨场记忆必须留下
- 忘掉失败时笔记还在不在、用户知不知道

**A2. 四件套（我的资产）**

档案页按场看产出；资产库筛选/标重要/改状态/确认决策/带入专访/拿去问。

必查：

- 观点、问题、知识债、重要标记：是本地 reducer + 整本 PUT，还是专用路由；autosave 失败时屏幕上的新状态还在不在
- 决策确认：是否走 `POST /api/assets/decisions/:id/confirm`（CAS）；已确认再点是 409 还是假绿
- 档案徽章按 `sourceSessionId` 过滤时，后来又出现过的资产会不会从这场档案里消失
- 「带入专访」带的是题目/模式/主题线哪几样；会不会不管原类型一律开成决策场
- 「拿去问」是否带着这条 id 进资产对话，还是只预填一句空话

**A3. 记忆**

待审列表：改字、批准（合并/新增）、拒绝、裁决矛盾；已确认：改写、弃用、删除、整理去重。

必查：

- 批准后下一场 `prefetchRecall` / `guide.relevantMemories` 是不是新字
- 用户改了候选再合并，改的字会不会被旧记忆盖掉
- 矛盾裁决按钮：路由、client、UI 三处是不是都在
- 敏感记忆默认不进上下文；配置打开后过滤是否真改
- 整理去重是可理解的合并还是黑箱删光

**A4. 素材库**

导入文本/文件 → 切块索引 → 抽出待审记忆 → 就资料提问。

必查：

- 导入 200 时 knowledge index / ragChunks 两边是不是都有；rebuild 失败是警告还是假成功
- 「去审核」是否真筛到这份来源的候选
- 「就资料提问」走资产对话还是页内死输入
- 敏感源会不会整份不可召回，文案有没有说

**A5. 资产对话**

问一句 → 回答带引用 → 点引用跳回笔记/记忆/素材/资产。

必查：

- 主路径是 `POST /api/chat` 还是 `POST /api/rag/query`；另一条是不是死路由
- `groundingMode`（有根据 / 部分 / 拒绝）是否到达气泡；没根据还像引了书 = 假闭环
- 引用的 sourceType/id 点回去是不是那一条
- 召回地板、敏感过滤、待审记忆是否与专访召回同一口径

**A6. 调研与播客**

简报生成/刷新/盯梢/带入专访/转成问题；从笔记或资产生成播客稿、确认、出声。

必查：

- 带入专访的题目是不是简报自己的题
- 自动盯梢默认关时灯和按钮是否一致
- 播客是否必须先确认再合成；主持和嘉宾是不是两个嗓子
- 从笔记/档案跳进播客是否带着对的笔记 id

#### B. 统一性（双真源 / 多写路径）

必须逐项对照，给出「谁赢」：

| 主题 | 真源候选 A | 真源候选 B | 运行时谁赢 | UI 展示谁 | 不一致时用户看见什么 |
|---|---|---|---|---|---|
| 观点/问题/债状态 | 本地 `update*Status` + PUT `/api/state` | （若仍有）专用 PATCH | | 资产库按钮 | |
| 决策确认 | `POST .../confirm` | 本地改 confirmationStatus | | 「确认决策」 | |
| 重要标记 | `toggleAssetImportance` 本地 | 服务端字段 | | 星标 | |
| 本场档案里有哪些资产 | `sourceSessionId === 这场` | `appearedInSessionIds` / 证据锚 | | 档案徽章 | |
| 长期记忆正文 | `memoryRecords` | 待审候选未批准 | | 记忆页 vs 下一场 prompt | |
| 对话根据 | knowledge index | `ragChunks` | 专访 `prefetchRecall` | 引用条 | |

| 忘掉笔记 | `POST /api/notes/:id/forget` | 本地滤 notes[] | | 笔记列表 | |

#### C. 闭环（人话）

用用户能听懂的话写六条，每条判定成不成立：

1. 我改一条观点的状态，刷新后再打开，还是我改过的那个字。
2. 我确认一条待确认的决策，下一场回访不再把它当「还没拍板」。
3. 我批准一条待审记忆（必要时先改字），下一场主持人能用到这句，而不是旧句或未批准的句。
4. 我打开一场笔记，能读到原文；忘掉这场（不勾连带）后，别的场共用的观点还在。
5. 我导入一份资料，资产对话问它能答到，并且点引用能回到这份。
6. 我从笔记生成播客，先看到稿，确认后才能出声。

列表里有、下一场 prompt 没有 = 假闭环。屏幕改了、整本保存失败刷新还原 = 半闭环。

#### D. 断点清单

至少覆盖：

- 改状态：离线、PUT 409 被别人覆盖、连点
- 确认决策：已确认再点、决策不存在、写锁冲突
- 忘掉笔记：不勾连带、勾了只属这场、勾了已确认记忆、笔记不存在
- 记忆：改字后合并、批准时嵌入失败、敏感条
- 导入：空正文、rebuild 失败、重复导入
- 对话：库空、引用失效、拒召
- 调研：无搜索钥匙、简报带入时今日台已有别的题
- 播客：未确认就合成、源笔记已忘掉

#### F. 结论一句

整组给一个总判：`能改也能被下一场用` / `能改但下一场不认` / `能看不能改` / `忘掉会误伤` / `对话在编书`。不要调和成「体验可优化」。

### 4. 必须逐个勾销的按钮/入口

不准漏（页面没有也要写「页无，代码有/无」）：

**双轨笔记**

- 打开一场 / 折叠原文
- 用此问题开场
- 把问题存成资产
- 打开主题 / 打开档案 / 生成播客
- 忘掉这场（默认 / 勾只属这场的产出 / 勾已确认记忆）

**我的资产 · 档案**

- 本场观点/问题/决策/债徽章（零的时候不能装有）
- 打开笔记
- 生成播客

**我的资产 · 资产库**

- 筛选四种 + 只看重要 + 排序
- 标重要
- 改观点/问题/债/决策状态
- 确认决策
- 带入专访
- 拿去问
- 打开来源场

**记忆**

- 改候选字 / 批准合并 / 批准新增 / 拒绝
- 裁决矛盾（若有）
- 改已确认 / 弃用 / 删除
- 整理去重
- 从素材跳来的来源筛选

**素材库**

- 导入正文 / 选文件
- 重建索引
- 去审核
- 就资料提问
- 删除一份素材

**资产对话**

- 发送
- 点引用
- 删整段对话

**外部调研**

- 生成简报 / 刷新 / 盯梢
- 带入专访
- 转成问题/债/观点

**播客**

- 选来源生成稿
- 确认这篇稿
- 合成声音
- 播放 / 重新合成

特别怀疑（允许证伪，不许跳过）：

1. 观点/问题/债/重要只改屏幕上的本本，靠稍后整本保存；保存失败或 409 覆盖后，用户以为改成了。
2. 决策确认是唯一走服务端的资产写；两边权威不一致时 UI 不说。
3. 「带入专访」一律开成决策模式，brief 传空，主题线不带。
4. 档案按 `sourceSessionId` 认场，后来又出现的证据让徽章变零。
5. 忘掉笔记勾连带时，删掉了别的场还在用的观点或已确认记忆。
