## 总判

能改也能被下一场用。笔记、记忆点头、决策确认、简报带进场、播客先确认再出声，书里对得上。问题在两处装忙：资产库「带入专访」经常开成另一场决策，档案徽章点进去可能对不上你刚看见的数。

## 人话（给用户看）

- 点了会发生的：改观点/问题/债的状态和重要（过一会儿整本存上）；确认待拍板的决策；笔记里用这个问题开下一场（会带着这条主题线）；忘掉这场默认不误伤别的场还在用的东西；待审记忆改字再批准，下一场用新字；导入资料能去审核、能就这份资料提问；资产对话有根据会标出来，没根据会拒；简报带进专访是学习场并挂上这份简报；播客先看稿，确认后才能出声。
- 点了是样子/会跑偏的：资产库「带入专访」总会新开一场「决策专访」，不带原来的主题线，还会清掉你手里那份简报；档案卡片上的数字，点进去可能变少（只认「出生场」，不认后来又出现过）。
- 改的时候注意：拧状态后如果马上开下一场，服务端可能还拿着旧本；确认决策的那一下如果撞上还没存上的本地改动，有可能把刚拧的状态盖回去。

## 闭环六句

1. 改一条观点状态，本页立刻变；刷新后是否还在，取决于 300ms autosave 是否成功。**本页成立；跨刷新/下一场有窗口。**
2. 确认待确认决策，走服务端 CAS，回访不再把它当没拍板。**成立。**
3. 改字再批准待审记忆，合并留下你批准的那句；下一场召回读 `memoryRecords`。**成立**（嵌入失败 502，本条未确认）。
4. 打开笔记能读摘要；原文走 raw-material，没有就说实话。忘掉这场（不勾连带）跨场观点留下。**成立。**
5. 导入资料后，「就资料提问」能问这份；资产对话问全书。点引用能跳回对应页。**成立**（两条问法范围不同，文案分开了）。
6. 从笔记生成播客，先确认稿再出声。**成立。**

## 断点

- 改状态：离线进 outbox；PUT 409 会跟服务器三方合并；连点只改本地同一份。
- 确认决策：已确认 409；不存在 404。
- 忘掉：二次确认口令 `DELETE_SESSION_NOTE`；不勾连带只拿走笔记/场/待审/这篇播客；勾了才动只属这场的抽出物/已点头记忆。
- 记忆：冲突候选默认拦截 409；改字后合并用新字；嵌入失败不装已确认。
- 导入：空正文不能点；向量未就绪警告。
- 对话：引用校验失败本轮不落库。
- 播客：未确认合成 409。
- 未在 demo 登录态真人点过这些按钮（本轮只读）。

## 发现

### P1 · 资产库「带入专访」开成另一场决策

- **现象**：你指着一条知识债或观点点「带入专访」，实际新开的是决策模式，题目变成「观点：某某」，不带原来的主题线，并且把当前选中的简报清掉。
- **证据**：`App.tsx:2430-2433` `launchInterview("decision", "", hint)`；`launchInterview` 会 `setActiveSearchBriefId(searchBriefId)`（`useInterviewSessionActions.ts:213-216`）；空串在创建时被当成没有简报（`startInterview` `searchBriefId ? { searchBriefId }`）。对照：笔记「用此问题开场」和调研「带入专访」都把模式/简报/主题线带对了。
- **点的哪个按钮**：我的资产 · 带入专访
- **书里少了什么**：不是没开场，是开错了场。
- **反驳**：确实会创建一场并跳进实时专访，不是死按钮。仍成立，因为用户指的那条线没带上。
- **等级**：CODE-CONFIRMED

### P1 · 拧状态/重要后马上开下一场或确认决策，可能还不认或被盖掉

- **现象**：观点状态、问题重要、债状态只改本机这本书，300ms 后才 PUT。下一场创建在服务端读仓库；这 300ms 里若去确认决策，且离线队列还没入队，`adoptServerState` 会用服务端旧本盖掉刚拧的状态。
- **证据**：`App.tsx:2423-2427` 本地 reducer；`useOfflineProductSync.ts:305-371` 300ms；`App.tsx:585-589` 无 pending 则整本采纳服务端；`assets.ts:8-13` 明确删掉了专用 PATCH。
- **点的哪个按钮**：标记重要 / 改状态，紧接着确认决策或开始专访
- **书里少了什么**：下一场 `statedPositions` / 回访队列仍可能是旧状态。
- **反驳**：停一下、看到存上再开场则成立。本地优先是有意设计。窗口真实存在，故仍记。
- **等级**：CODE-CONFIRMED

### P2 · 档案徽章和点进去的列表不是同一把尺

- **现象**：档案卡按「这场出现过」数徽章；点徽章进资产库只留下「出生在这场」的。
- **证据**：`session-archive.ts:26-38` vs `AssetsView.tsx:253-259`
- **点的哪个按钮**：本场 N 观点 / N 债
- **书里少了什么**：合并后又在这场出现的资产，卡片有、列表无。
- **反驳**：全局资产库不带场次过滤时仍能看到。钻取路径撒谎。
- **等级**：CODE-CONFIRMED

### P2 · 「问资产」不把这条资产交给检索

- **现象**：只预填一句「关于我的观点「…」」，对话按普通提问召回，不保证引用就是这一条。
- **证据**：`App.tsx:2435-2438`
- **点的哪个按钮**：问资产
- **反驳**：会打开对话，不是死按钮。检索没有 id 约束。
- **等级**：CODE-CONFIRMED
