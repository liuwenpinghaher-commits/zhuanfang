## Prompt 正文（从这里开始复制）

你要对 **专访（zhuanfang）的「访谈工作台」** 做一次彻底审查。

侧栏这一组有三页：

- **今日访谈台**（`home`）`src/features/home/HomeView.tsx`
- **实时专访**（`interview`）`src/features/interview/InterviewView.tsx`
- **主题线**（`themes`）`src/features/themes/ThemesView.tsx`  
  从主题点进去的 Track 工作区算爆炸半径，不当主审范围。

产品是语音专访式认知工具。工作台不是三张说明书，是同一条活：进来、谈完、留下。用户体感如果「全是问题」，通常是：按钮在、灯在、话也说了，书里却没那场、没那句、或结束了像没发生。

不要先辩解产品设计。先用当前代码证明：哪个按钮点下去，这场/下一场书里真发生了那一件事；哪个只是样子；哪个点了会把这场写脏。

工作台同时管五件不同的事，必须分开记账，不许揉成「访谈模块都有」：

1. **进场**：开一场 / 继续一场 / 扔掉空场；模式、题目、主题线有没有真带进这一场
2. **文字谈**：一问一答写进这场；失败能看见、能重试；控制键真改这一场
3. **语音谈**：能听见主持人、你说话他听得见、真抢话才打断；三套语音栈（级联 / 百炼直通 / LiveKit）会不会各写各的
4. **结束**：点结束留下笔记和待审记忆；「本次不保存」真的不留档案；录音/逐字稿有没有跟着走
5. **带回下一场**：今日台推荐、回访队列、主题「接着访」是不是把同一条线带进下一场，而不是另起炉灶

审查目标不是再写说明书，而是回答：

1. 点了「开始 / 发送 / 麦克风 / 结束」，书里有没有这一场、这一句、这份笔记？
2. 失败时用户看见什么？装成功、吞掉、还是能重试？
3. 三套语音是不是同一本账（turns、打断、录音、主持句）？
4. 今日台卡片、回访队列、主题线，是真入口还是死展览？
5. 连点、离线、谈着切页、空场扔掉，会不会盖掉刚说的话？

### 1. 发现准入

每条最终发现必须有：

- `file:line` 或 HTTP 输出
- 用户点的是哪个按钮/键
- 走哪条写路径（client 方法、路由、域函数、冷层）
- 下游谁读（点名函数，不要说「应该会读」）
- 失败时用户看见什么（toast / 输入框还在 / 场还在 / 装结束）
- 反驳：为什么可能不是问题，为何仍成立或降级为疑点

证据等级：`CONFIRMED` / `CODE-CONFIRMED` / `PLAUSIBLE` / `REGRESSION-SEED`。

严重度：

- `P0`：说了的话没进书、结束了档案没了却报成功、一场盖另一场、未登录能谈
- `P1`：核心进场/发送/结束生产不可达；语音听得见但 turns 不落；控制键假成功
- `P2`：推荐/回访/主题入口是死展览；三套语音账不一致；降级无信号
- `P3`：文案、测试盲区、页内重复入口

### 2. 怎么审（方法，不要按三页分区扫完就算）

**先建「按钮 → 书里发生什么」账本，再进页面。** 禁止只读 HomeView/InterviewView 就下结论。

对每一个入口问四句：

1. 页面上有没有这个按钮？可点还是灰的？
2. 点下去写到哪？`POST /api/interview-sessions` / `/turns` / `/end` / 只 setState / 其实没写？
3. 运行时谁读？下一句 prompt、笔记 finalize、记忆候选、录音仓库、知识块，是不是同一场 id？
4. 没写上或写错场时，用户怎么发现？红条？输入还在？静默丢句？

结论只许四选一：`点了会发生` / `点了要等下一场才发生` / `点了是样子` / `有意未开`。

配置页审的是格子；工作台审的是动作。不要把「模式枚举有六种」当成闭环。

### 3. 必须交的六张答卷

#### A. 接线账

最少追这些，缺一条不算审完：

**A1. 进场**

今日台 / 主题 / 其它页的 `onStart` → `App.launchInterview` → `useInterviewSessionActions.startInterview` / `launchInterview` → `POST /api/interview-sessions`。

必查：

- `mode`、`topicHint`、`relatedThemeIds`、`searchBriefId` 有没有进创建 payload 和这场的 card/guide
- 今日台「继续」是装回已有 active session，还是又开一场
- 「扔掉空场」走 `discardInterviewSession`；有用户句时能不能扔掉
- 连点开始会不会开两场（`startingRef` / 进行中锁）

**A2. 文字一轮**

输入框提交 → `submitTurn` → `POST .../turns` 或 `/turns/stream` → 域 `receiveTurn` / interviewer-brain → 用户句+主持句落这场。

必查：

- 失败（503/429/502/超时）用户句在不在；输入框会不会被清空
- `retryAvailable` 重试的是哪一句
- 取消/打断是否留下鬼主持句

**A3. 语音一轮**

麦克风 → `useRealtimeVoiceControls` / `startRealtimeVoiceConnect` → 按 `systemConfig.voice.realtimeMode` 分 cascade / bailian / livekit。

必查：

- 三套栈的用户句、主持句是不是都进同一 `session.turns`
- 级联 TTS 声从哪来（产品默认声 vs env）
- 抢话：本地停播 vs 服务端截断主持句
- 转写待确认（quarantine）确认前会不会先写入
- 没开场就点录音：是拦住还是空转

**A4. 控制键**

`InterviewView` 的节奏/方向/边界 → `applyInterviewControl` → 哪条路由或只写 `pendingControl`。

必查每个键：`softer` `summary` `different-angle` `sharper` `skip` `do-not-save`。下一句 prompt 有没有吃到；`do-not-save` 在 `/end` 是否真不落笔记。

**A5. 结束**

结束按钮 → `finishInterview` → `POST .../end` → finalize 笔记/资产/待审记忆；录音上传；逐字稿降冷。

必查：

- 成功回执和书里实际 notes/candidates 是否一致
- 失败时场是不是还在、用户知不知道能重试
- `doNotSave` 仍上传录音/索引没有
- 结束后今日台「刚结束」摘要是真数还是本地凑的

**A6. 主题带回**

主题「接着访」→ `launchInterview("long-term", hint, [theme.id])`。

必查：`relatedThemeIds` 是否进 session，结束笔记是否挂这条线，回访队列点下去是不是同一条。

#### C. 闭环（人话）

用用户能听懂的话写五条，每条判定成不成立：

1. 我在今日台开一场日常复盘，实时专访里是不是这场，题目是不是我填的。
2. 我打一行字发出去，过一会儿能不能看见主持人的下一问，刷新后还在。
3. 我开口说话，能不能听见主持；我抢话，他是不是真停。
4. 我点结束，笔记页有没有这场；待审记忆能不能点头。
5. 我从一条主题线接着访，这场是不是还挂着这条线。

只出声不落 turns = 假闭环。只落 turns 结束没有笔记 = 半闭环。

#### D. 断点清单

至少覆盖：

- 开始：无题目、连点、已有 active 场再开、后端 503
- 发送：空句、超时、预算用尽、离线
- 录音：权限拒绝、浏览器拦住自动播放、连接耗尽
- 控制：场已结束还点、`do-not-save` 后再想保存
- 结束：finalize 半失败、录音上传失败、空场结束
- 切页：谈到一半回今日台再继续，是不是同一场
- 主题：没有主题时「接着访」

#### F. 结论一句

整组给一个总判：`能谈完一场` / `能说但不能留下` / `三套嘴各说各的` / `入口是展览结束是黑洞`。不要调和成「体验可优化」。

不准漏（页面没有也要写「页无，代码有/无」）：

特别怀疑（允许证伪，不许跳过）：

1. 今日台推荐的 mode/topic 点开始时被 `pendingMode` 或空 hint 盖掉。
2. 语音用户句靠前端再记一份，和 `/turns` 双写或漏写。
3. Omni / LiveKit 主持句不进 `recordInterviewTurn`，级联才进。
4. `buildRealtimeTurnState` 的留白只改旁白，真正开口时机在 cascade `minPauseMs`（配置审查已接线，要复核工作台这条活路径还在不在）。
5. `do-not-save` 只改文案，`/end` 仍 finalize。
6. 扔掉空场在离线时本地删、重连又回来或反过来把有内容的场滤掉。
7. 结束成功 toast 时笔记还没有（finalize 异步/失败吞掉）。
8. 主题接着访没带 `relatedThemeIds`，笔记挂不上这条线。
