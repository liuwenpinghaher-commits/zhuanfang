## 1. 林越

我叫林越，做 AI coding agent 的，公司现在六十来人。我先说个我差点把公司做没的决定吧。去年 Q3 我赌模型的 long-context 半年后会便宜十倍，于是把整个产品架构压在'全量塞上下文'上，砍掉了我们辛苦做了三个月的检索召回模块。结果模型降价比我预期晚了快两个季度，那几个月我们的成本结构直接崩了，烧钱速度翻倍。最难受的是，团队里有人当时反对，我没听。后来我才明白，创业不是赌技术对不对，是赌你能不能活到你赌的那件事发生。

## 2. 主持人

当时反对你的具体是谁？他当时说了什么，让你决定直接砍掉那三个月的成果？

## 3. 林越

反对我最凶的是我们CTO老陈，跟我从前大厂基础架构一起出来的兄弟。那天他拿着压测报告直接拍我桌上：“林越你疯了吧？现在128k窗口推理延迟平均8秒，并发一高直接OOM。咱们那套RAG（检索召回）虽然笨，但首字响应1.5秒，客户用得挺爽。你为了赌半年后模型降价，把现在的护城河拆了？”

他说的全是工程现实，但我为什么还是砍了？因为我太清楚Coding Agent的终局了。Coding不是简单的代码补全，是理解整个代码库。RAG的召回率有物理天花板，遇到跨几十个文件的复杂重构，RAG就是个智障，经常漏关键上下文。我当时跟老陈拍桌子：“如果我们只守着一个1.5秒响应的工具，那跟套壳有什么区别？Agent的边界正在消弭，它必须能看懂全量上下文。模型半年后绝对会便宜十倍，长文本推理也会优化，我们现在不推翻重来，半年后连上牌桌的资格都没有！”

说白了，我赌的是“模型即OS”的演进速度。但我狠狠打脸了，我高估了底层模型优化的速度，也低估了全量上下文带来的工程灾难。结果老陈带着五个人熬了两个月大夜重构，上线后API成本直接翻倍，差点把公司现金流干断。做bet不能只赌技术方向，还得算算自己的血条够不够撑到黎明。你说，如果是你，这1.5秒的爽和8秒的真，你选哪个？

## 4. 主持人

我选能让公司活到黎明的那个。但你当时拍桌子说“太清楚Coding Agent的终局了”，这个“太清楚”，是看到了某个跑通全量上下文的真实demo，还是纯粹对技术演进的信仰？

## 5. 林越

不是纯信仰，是真看到了一个让我头皮发麻的demo。去年2月，Opus刚上，我们内部一个极客小伙，拿我们还没上线的框架，硬塞了大概15万token的上下文——直接是一个中型开源项目的全量代码，让它去修一个跨了十几个文件的并发bug。

那体验简直是灾难，推理跑了快两分钟，中间还断了两次。但当它最终吐出代码的时候，我鸡皮疙瘩起来了。它不仅改对了底层逻辑，还顺手重构了上层两个看似没关联的调用接口，因为它“看”到了全局的数据流向。那一刻我彻底明白，RAG那种“盲人摸象”的检索，在复杂工程面前就是个笑话。

所以我跟老陈拍桌子，不是因为我觉得今天的模型牛逼，而是我确信 Coding Agent 的终局就是“模型即 OS”。只要上下文够大，Agent 的边界就会消弭，它自己就能理解整个代码库。我赌的是半年后，模型处理长文本的能力会跨过临界点，且成本降到能用。

但我确实被打脸了。我赌对了终局，却赌错了节奏。那个demo让我上头，让我以为半年后底层就能完美解决长文本的工程问题。结果呢？成本没降，OOM（内存溢出）反而更严重。信仰没毛病，但创业不能只靠信仰，还得算账。你说，看到那种降维打击的demo，有几个创业者能忍住不All in？

## 6. 主持人

## 7. 林越

说实话，当时心里绝对是“只要结果对，工程问题以后再说”。你别笑，我一个搞了十年基础架构、天天跟SLA（服务可用性）死磕的人，说出这话自己都觉得扯淡。但当时那个demo给我的震撼太大了，它改出了人类资深架构师都要看半天的并发逻辑。我当时脑子里的OS是：只要它能把这15万行代码的逻辑盘明白，两分钟算什么？断两次算什么？大不了我们做个异步任务，后台跑，跑完给个回调通知嘛。

这就是我犯的第一个致命错误：我用“技术终局”去掩盖了“产品体验的残缺”。后来产品真灰度上线，用户根本不买账。你以为开发者有耐心等两分钟？你断两次试试？客服群直接炸了。PMF真不是我们在会议室里看着demo“找”到的，是被用户用脚投票“用”出来的。用户不关心你后台是不是塞了全量上下文，不关心你的Agent是不是理解了全局，他们只关心“我按下回车，3秒内能不能给我首字反馈”。

那断掉的两次，其实是产品形态在向我报警。但我当时被“模型即OS”的宏大叙事冲昏了头，觉得工程问题都是dirty work，赌模型半年后自己就能解决。结果呢？模型没解决，我们的工程团队为了擦屁股，加了无数的降级和兜底逻辑，原来的优雅架构被改得像屎一样。所以啊，创业千万别为了赌一个浪，把冲浪板给扔了。你现在觉得“工程以后再说”，往往是因为你还没想清楚这玩意儿到底怎么让普通人爽。

## 9. 林越

这句话直接把我干破防了。公司过60人，组织的第一道坎真来了——信息密度和决策速度开始严重打架。我每天脑子里想的是“模型即OS”、“Agent边界消弭”，盯的是一年后；但老陈和兄弟们面对的是今天的客诉、是那个两分钟响应的烂架构、是见底的现金流。

他骂得对。创业最重要的是 make the bet，赌一个浪，但我不能为了自己冲浪，把板子砸了让兄弟们在海里扑腾。我赌了模型长文本的演进，却没算进组织消化的摩擦力。那天之后我彻底认怂，让老陈把RAG和长上下文做了个动态路由，先保3秒首字响应。PMF真不是我们在会议室里过度设计出来的，是被用户用出来的。要不是老陈那顿骂把我拽回来，我可能真带着全公司给AGI殉道了。
