# Phase 1 Drizzle SQLite State Store Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans and superpowers:test-driven-development to implement this plan task-by-task.

**Goal:** Move the API persistence boundary from process memory to a local database-backed repository while keeping Redis deferred and Prisma out of the primary path.

**Architecture:** Add `packages/db` for schema and repository code. Drizzle owns the table definitions and migration SQL shape; the local development repository uses Node's built-in SQLite runtime so the demo can run without a Postgres service. `ProductStateRepository` remains the API-facing contract, allowing a later Postgres repository to replace the SQLite implementation.

**Tech Stack:** TypeScript, Drizzle ORM schema definitions, Node `node:sqlite`, Vitest.

---

## File Structure

- Modify: `package.json` - add Drizzle dependency.
- Modify: `package-lock.json` - generated by npm install.
- Modify: `vite.config.ts` - include `packages/**/*.test.ts` already supported.
- Create: `packages/db/src/schema.ts` - Drizzle table definitions for product state snapshots and state events.
- Create: `packages/db/src/sqlite-product-state-repository.ts` - SQLite implementation of `ProductStateRepository`.
- Create: `packages/db/src/sqlite-product-state-repository.test.ts` - repository persistence tests.
- Modify: `apps/api/src/product-state-repository.ts` only if the repository contract needs async compatibility.
