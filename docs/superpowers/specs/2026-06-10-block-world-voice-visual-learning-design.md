# 方块世界语音图形化儿童思维成长工具方案

版本：v0.1  
日期：2026-06-10  
目标用户：7-12 岁儿童，首个目标孩子 8 岁  
产品方向：儿童独立使用的语音驱动方块世界学习工具  

---

## 0. 结论

这个产品不应做成普通 AI 聊天工具，也不应做成直接复制 Minecraft 的产品。最优形态是：

> 一个原创方块沙盒风格的儿童思维成长工具。孩子用语音表达想法，系统把语音自动转成任务、地图、蓝图、背包、NPC 追问和成长记录，用孩子喜欢的方块世界训练表达、规划、逻辑、创造、复盘和 AI 素养。

核心闭环：

```text
孩子说一个想法
→ 实时语音识别
→ AI 理解孩子意图和学习目标
→ 生成结构化 Scene DSL
→ 安全与规则校验
→ 方块地图 / 蓝图 / 任务卡实时变化
→ NPC 追问 2-3 轮
→ 孩子补充解释
→ 系统记录能力表现
→ 每周生成作品和家长周报
```

第一版建议采用：

```text
React + Phaser 或 PixiJS
+ 国内实时 ASR
+ LLM 结构化输出
+ 原创 2D 等距方块地图
+ 家长周报
+ 儿童安全与隐私保护
```

不要在 MVP 阶段直接做完整 3D、开放聊天、社交、排行榜、商城或真实 Minecraft 深度绑定。

## 1. 背景与机会

### 1.1 用户洞察

孩子已经喜欢和豆包聊“我的世界”，说明他的兴趣入口不是传统学习任务，而是：

- 方块建造
- 沙盒创造
- 冒险探索
- 红石逻辑
- 村民/NPC 对话
- 任务与地图变化
- 自己设计一个世界

这类兴趣天然适合培养未来能力：

- 建造前需要规划。
- 设计结构需要空间思维和数学估算。
- 红石/机关对应逻辑与因果。
- 冒险日志对应叙事表达。
- 建造失败后改造对应复盘和韧性。
- 判断游戏传闻真假对应信息素养和 AI 素养。

产品策略不是把孩子从兴趣里拉出来学习，而是把兴趣改造成学习引擎。

### 1.2 教育目标

产品长期培养七类能力：

1. 表达能力：把想法说完整、说清楚。
2. 分析思维：能解释原因、比较方案、识别风险。
3. 创造性思维：能提出原创设计和替代方案。
4. 数学与逻辑：能估算材料、布局、路线和条件关系。
5. 科学与项目探究：能观察、假设、测试、记录、改进。
6. 元认知：能复盘哪里难、下次怎么改。
7. AI 与信息素养：知道 AI 和网络信息可能出错，需要验证。

### 1.3 产品边界

产品不是：

- AI 陪伴朋友
- 开放式角色扮演聊天
- 普通题库或 AI 家教
- Minecraft 官方产品
- 社交游戏
- 考试提分工具

产品是：

- 方块世界任务教练
- 儿童语音表达训练器
- 项目式学习引导器
- 成长档案系统
- 家长低负担观察工具

## 2. 产品定位

### 2.1 一句话定位

面向 7-12 岁儿童的 AI 方块世界思维成长工具，通过语音对话自动生成任务地图和建造蓝图，让孩子在“像玩方块冒险”的体验中训练表达、规划、逻辑、创造和复盘。

### 2.2 核心价值

对孩子：

- 用自己喜欢的方块世界做任务。
- 说话就能让地图和蓝图变化。
- 不像上课，更像冒险和建造。
- 每天 10 分钟能完成一个小闭环。
- 每周能留下一个真实作品。

对家长：

- 不需要每天陪学。
- 每周 3-5 分钟看报告。
- 能知道孩子在表达、逻辑、项目、复盘上的变化。
- 有安全边界，不让孩子陷入开放 AI 聊天。
- 兴趣没有被压制，而是被转化成成长动力。

### 2.3 产品名称方向

正式命名不要使用 Minecraft 作为主标题。

可选方向：

- 方块思维岛
- 方块冒险课
- 小小建造师
- 方块任务官
- 未来方块岛

如果需要提及 Minecraft，只能在介绍中表达“适合喜欢 Minecraft/方块沙盒的孩子”，并遵守相关品牌和商业使用规则。

## 3. 核心用户与使用场景

### 3.1 主用户：孩子

年龄：7-12 岁，首个目标 8 岁。  
使用方式：孩子自己使用，家长少量参与。  
输入方式：语音优先，文字备用。  
单次时长：每日 8-15 分钟。  
设备优先级：平板 > 电脑 > 手机。

孩子端设计原则：

- 页面少字。
- 一次只给一个明确任务。
- 反馈具体，不空泛表扬。
- 控制 AI 对话轮数。
- 所有游戏奖励都绑定真实思考行为。

### 3.2 次用户：家长

家长不负责每日陪聊，只负责：

- 初次同意和设置。
- 每周查看成长报告。
- 必要时查看安全提醒。
- 调整任务方向和使用时长。

家长端设计原则：

- 不做复杂大屏。
- 不展示大量原始聊天。
- 用一页报告说明孩子本周做了什么、表现如何、下周建议是什么。
- 提供数据删除、导出、隐私设置。

## 4. 产品主循环

### 4.1 每日 10 分钟循环

```text
打开产品
→ 今日冒险任务
→ NPC 提出一个方块世界问题
→ 孩子语音回答
→ 系统实时生成字幕
→ 系统把回答转成地图/蓝图变化
→ NPC 追问 2 轮
→ 孩子补充解释
→ 生成今日成长点
→ 世界增加一个方块、建筑、道具或徽章
```

示例：

```text
任务：给河对岸的图书馆造一座桥

孩子说：
我想用石头建桥，因为木头可能会被烧掉，桥中间要高一点，船可以过去。

系统生成：
- 河流地图
- 石桥蓝图
- 中间拱起的桥面
- 材料背包：石头、台阶、火把
- 追问：如果石头不够，你会先保留桥的哪一部分？
```

### 4.2 每周项目循环

```text
周一选择大工程
→ 周二规划区域
→ 周三计算材料
→ 周四解决一个问题
→ 周五改进设计
→ 周六完成作品展示
→ 周日复盘并生成家长周报
```

示例项目：未来学校。

```text
第 1 天：学校需要哪些区域？
第 2 天：教室、图书馆、运动场怎么摆？
第 3 天：每个区域大约需要多少方块？
第 4 天：如果学生迷路怎么办？
第 5 天：加入一个 AI 助手，但说明它不能替学生做什么。
第 6 天：录一段 1 分钟展示。
第 7 天：复盘：我最满意哪里？下次想改哪里？
```

### 4.3 长期成长循环

```text
每日回答
→ 结构化能力观察
→ 每周项目作品
→ 能力趋势
→ 家长周报
→ 下周任务推荐
```

## 5. 功能模块

### 5.1 孩子端首页

只显示四个入口：

```text
今日冒险
本周大工程
我的方块世界
我的作品展
```

首页不展示：

- 复杂设置
- 模型信息
- 家长报告
- 开放聊天入口
- 排行榜
- 商城

### 5.2 今日冒险

任务类型：

1. 建筑挑战：训练规划、空间、数学估算。
2. 村民求助：训练表达、换位思考、方案解释。
3. 红石谜题：训练逻辑、因果、条件判断。
4. 探险日志：训练叙事、观察、复盘。
5. 真假消息站：训练信息判断和 AI 素养。
6. 失败修复站：训练韧性和迭代。

任务固定结构：

```text
故事引入
→ 任务目标
→ 孩子回答
→ 地图变化
→ NPC 追问
→ 孩子补充
→ 今日成长点
→ 世界奖励
```

### 5.3 语音生成图形化

这是产品核心能力。

孩子的自然语言不直接生成图片，而是转成结构化游戏状态：

```text
语音
→ 转写文本
→ 意图识别
→ 学习目标识别
→ Scene DSL
→ 规则校验
→ 游戏引擎渲染
```

可生成的图形化信息：

- 方块地图
- 建筑蓝图
- 材料背包
- NPC 对话气泡
- 任务卡
- 危险标记
- 方案对比图
- 路线图
- 项目进度地图
- 作品展示页

### 5.4 NPC 追问系统

NPC 不做陪伴型聊天，只做任务型追问。

角色建议：

- 方块导师：发布任务。
- 红石工程师：追问逻辑和因果。
- 图书管理员：追问阅读、资料和真假判断。
- 探险记录员：引导复盘。
- 挑刺村民：提出反方问题。
- 安全守卫：处理隐私、危险和沉迷提醒。

追问原则：

- 每次最多 2-3 轮。
- 追问围绕学习目标。
- 不评价孩子人格。
- 不诱导长时间聊天。
- 不替孩子直接完成答案。

示例追问：

```text
你为什么这样设计？
如果材料不够，你先保留哪个部分？
有没有另一种方案？
这个办法可能哪里会失败？
如果你再做一次，会改哪里？
```

### 5.5 每周大工程

第一批项目模板：

1. 纸桥挑战
2. 未来学校
3. 山顶秘密基地
4. 安全村庄防御
5. 自动农场规划
6. 图书馆迷宫
7. 节水小镇
8. 太空基地

每个项目都要绑定能力目标：

```text
项目目标
学习能力
每日步骤
需要表达的问题
需要估算的数量
需要改进的地方
最终作品
复盘问题
```

### 5.6 我的方块世界

世界不是无限游戏，而是成长档案的可视化表达。

世界区域：

- 表达村：孩子完成表达任务后扩建。
- 红石工坊：完成逻辑任务后解锁装置。
- 图书馆：完成阅读和真假判断后增加书。
- 实验岛：完成科学项目后增加实验设施。
- 复盘塔：完成复盘后升高一层。

每个区域代表能力成长，不是单纯装饰。

### 5.7 家长周报

周报结构：

```text
本周完成
- 5 次今日冒险
- 1 个大工程
- 3 次复盘

本周亮点
- 孩子能更清楚解释“为什么这样设计”
- 对工程类任务更投入

需要支持
- 回答风险问题时容易只说“不会坏”
- 下周建议多做方案比较任务

代表作品
- 山顶秘密基地蓝图

安全提醒
- 无异常 / 有一次隐私提醒 / 有一次超时提醒
```

## 6. 语音到图形化技术方案

### 6.1 不推荐路线：语音直接生成图片

语音直接生成图片适合做：

- 项目封面
- 徽章
- 作品海报
- 周报插图

不适合作为核心交互，因为：

- 生成慢。
- 不稳定。
- 不可交互。
- 难以验证材料、坐标、规则。
- 难以形成成长数据。
- 难以保证儿童安全边界。

### 6.2 推荐路线：语音生成 Scene DSL

核心思想：

```text
孩子说的话不是直接变成图片，而是变成“游戏世界更新指令”。
```

Scene DSL 示例：

```json
{
  "version": "0.1",
  "quest": {
    "id": "daily_bridge_001",
    "type": "build_challenge",
    "title": "给图书馆造一座桥",
    "learningGoals": ["planning", "risk_analysis", "explain_reason"]
  },
  "scenePatch": {
    "biome": "river_village",
    "camera": "isometric",
    "objects": [
      {
        "id": "river_1",
        "type": "river",
        "position": {"x": 3, "y": 4},
        "size": {"w": 6, "h": 2}
      },
      {
        "id": "bridge_1",
        "type": "bridge",
        "material": "stone",
        "position": {"x": 4, "y": 4},
        "size": {"w": 4, "h": 1},
        "labels": ["石桥", "中间抬高"]
      }
    ]
  },
  "inventory": [
    {"item": "stone_block", "count": 20},
    {"item": "torch", "count": 4}
  ],
  "npc": {
    "role": "redstone_engineer",
    "question": "如果石头不够，你会先保留桥的哪一部分？为什么？"
  },
  "assessmentHints": {
    "observed": ["gave_reason", "considered_risk"],
    "nextPromptType": "tradeoff"
  }
}
```

### 6.3 结构化生成要求

LLM 输出必须满足：

- JSON Schema 校验。
- 枚举字段白名单。
- 地图尺寸限制。
- 对象数量限制。
- 材料类型限制。
- 学习目标必须从固定能力模型中选择。
- 不允许生成危险、成人、隐私、暴力强化内容。
- 不允许生成真实 Minecraft 官方素材或商标元素作为商业产品核心资产。

### 6.4 图形渲染方案

MVP 使用 2D 等距方块地图。

推荐技术：

- Phaser：适合游戏状态、任务流程、地图、输入、动画。
- PixiJS：适合高性能 2D WebGL 渲染，和 React 结合灵活。

第二阶段可升级：

- Three.js：3D 方块世界。
- Babylon.js：更完整 3D 游戏引擎。

MVP 渲染对象：

```text
地形：草地、河流、山、雪地、沙地
建筑：桥、小屋、图书馆、基地、农场、实验室
道具：木板、石头、玻璃、火把、门、按钮
标记：危险、问题、目标、完成
NPC：导师、工程师、图书管理员、记录员、安全守卫
UI：任务卡、背包、蓝图、对话气泡、能力徽章
```

## 7. 推荐技术架构

### 7.1 总体架构

```text
Web / Tablet App
  - React UI
  - Phaser/PixiJS Renderer
  - Voice Capture
  - Child Task UI

Backend Orchestrator
  - Session API
  - ASR Adapter
  - LLM Adapter
  - Scene DSL Generator
  - Safety Validator
  - Growth Assessment
  - Parent Report Generator

Persistence
  - child_profile
  - quest_sessions
  - transcripts_summary
  - scene_states
  - project_artifacts
  - assessment_events
  - parent_reports
  - safety_events
```

### 7.2 语音层

国内优先方案：

- 火山引擎/豆包语音
- 腾讯云实时语音识别
- 阿里云实时语音识别
- 科大讯飞实时语音转写

选择标准：

- 中文儿童语音识别准确率。
- 方言和中英混说支持。
- 实时延迟。
- WebSocket 稳定性。
- 数据合规和地域。
- 成本。

前端使用浏览器 `getUserMedia` 采集麦克风，后端通过 WebSocket 转发到 ASR 服务。不要把云厂商密钥放在前端。

### 7.3 LLM 层

可选：

- 豆包/火山方舟
- 通义千问
- OpenAI
- 其他支持结构化输出或 Function Calling 的模型

关键不是选择哪个模型，而是架构上必须做到：

- LLM 只生成候选 Scene DSL。
- 后端校验后才写入世界状态。
- 不合规输出被拒绝或修复。
- 安全规则优先级高于模型输出。
- 所有能力评估只作为观察，不给孩子贴负面标签。

### 7.4 安全校验层

校验器职责：

- Schema 校验。
- 敏感内容过滤。
- 隐私信息检测。
- 坐标和对象数量限制。
- 任务时长限制。
- 禁止开放陪伴对话。
- 禁止作业代写。
- 禁止危险行为指导。
- 生成内容标识。

### 7.5 数据存储策略

默认不保存原始音频。

建议保存：

- 转写后的必要文本片段。
- 结构化任务结果。
- 场景状态。
- 能力观察事件。
- 作品数据。
- 家长周报。
- 安全事件。

不建议保存：

- 长期原始录音。
- 真实姓名、学校、住址。
- 无关聊天内容。
- 可识别儿童身份的照片原图，除非有明确监护人同意和删除机制。

## 8. 儿童安全与合规

### 8.1 产品安全原则

产品必须是任务型 AI，不是陪伴型 AI。

必须避免：

- 无限开放聊天。
- AI 声称自己是真实朋友。
- 情感依赖设计。
- 成人、暴力、危险内容。
- 作业代写。
- 上传隐私。
- 社交排名。
- 抽卡和沉迷机制。

### 8.2 中国合规重点

面向 8 岁儿童时，需要按不满 14 周岁儿童个人信息处理：

- 取得监护人同意。
- 制定专门儿童个人信息处理规则。
- 最小必要收集。
- 加密存储。
- 严格权限控制。
- 第三方处理安全评估。
- 支持更正、删除、注销。
- 防范未成年人过度依赖或沉迷生成式 AI。

### 8.3 美国和国际参考

如果面向美国市场，需要考虑 COPPA：

- 父母控制儿童数据收集。
- 可验证父母同意。
- 清晰隐私通知。
- 数据删除和访问机制。

UNICEF 儿童 AI 指南强调：

- 儿童安全。
- 数据和隐私保护。
- 公平和非歧视。
- 透明和可解释。
- 支持儿童最佳利益和发展。

### 8.4 产品内安全设计

孩子端：

- 单次任务 10-15 分钟收束。
- 每日建议上限。
- 敏感内容触发“找家长”提醒。
- 隐私内容触发安全守卫。
- AI 不继续追问隐私。

家长端：

- 使用时长设置。
- 数据删除。

## 10. 第一批任务模板

### 10.1 建筑挑战：河上图书馆桥

目标能力：

- 规划
- 解释理由
- 风险分析

任务：

```text
河对岸有一座图书馆，村民过不去。
请你设计一座桥。
```

追问：

```text
你为什么选这种材料？
桥最容易坏的地方在哪里？
如果材料不够，你先保留哪一部分？
```

图形化输出：

- 河流
- 图书馆
- 桥梁蓝图
- 材料背包
- 风险标记

### 10.2 红石逻辑：自动门

目标能力：

- 条件判断
- 因果推理
- 顺序表达

任务：

```text
实验室需要一扇自动门。
你要说明按钮、门和线路之间的关系。
```

追问：

```text
按钮按下后第一件事发生什么？
如果门打不开，可能是哪一步坏了？
```

### 10.3 探险复盘：山洞路线

目标能力：

- 叙事表达
- 顺序组织
- 复盘

任务：

```text
你发现了一个山洞。
请讲清楚你从哪里进去、看见了什么、遇到什么危险、最后怎么出来。
```

追问：

```text
如果下次再进去，你会准备什么？
哪个地方最容易迷路？
```

### 10.4 真假消息站：钻石传闻

目标能力：

- 信息判断
- 证据意识
- AI 素养

任务：

```text
一个村民说：钻石一定在岩浆旁边。
你觉得这句话一定对吗？怎么验证？
```

追问：

```text
你需要几次观察才更有把握？
如果 AI 也这样说，你会直接相信吗？
```

## 11. 成长评估模型

### 11.1 不做分数排名

不建议给孩子显示：

- 逻辑 60 分
- 表达 70 分
- 超过 80% 同龄人
- 排名

建议显示：

- 今日完成了一个好解释。
- 你提出了一个新问题。
- 你找到了一个可能失败的地方。
- 你改进了自己的方案。

### 11.2 后台记录能力事件

能力事件示例：

```json
{
  "childId": "child_001",
  "sessionId": "session_123",
  "eventType": "gave_reason",
  "domain": "expression",
  "evidence": "因为木头可能会被烧掉，所以我想用石头",
  "confidence": 0.82,
  "visibleToChild": false
}
```

能力事件类型：

- gave_reason：说明理由
- compared_options：比较方案
- identified_risk：识别风险
- asked_question：主动提问
- revised_plan：修改方案
- reflected_failure：复盘失败
- used_evidence：使用证据
- estimated_quantity：数量估算

### 11.3 家长报告表达方式

对家长说：

```text
本周孩子更愿意解释“为什么这样设计”。
在 5 次任务中，有 4 次能给出原因。
下周建议增加“比较两个方案”的任务。
```

不要说：

```text
孩子逻辑能力较差。
孩子表达落后。
孩子缺乏创造力。
```

## 12. 路线图

### 阶段 1：交互闭环原型，2-4 周

目标：验证孩子是否愿意用语音让方块世界变化。

范围：

- 10 个任务模板。
- 文本/语音输入二选一。
- 2D 方块地图 demo。
- LLM 输出 Scene DSL。
- NPC 追问 1-2 轮。

验收：

- 孩子能在 10 分钟内完成任务。
- 系统能稳定把回答转成地图变化。
- 孩子愿意继续下一天使用。

范围：

- 40 个每日任务。
- 8 个每周项目。
- 作品展。
- 能力事件记录。
- 家长周报。

验收：

- 7 日留存有可观察数据。
- 每日任务完成率可统计。
- 每周项目能完成一个作品。
- 家长能理解报告并调整任务方向。

### 阶段 3：内测版，8-12 周

范围：

- 更丰富方块世界。

- 安全事件工作台。

### 阶段 4：商业版

目标：订阅和规模化。

范围：

## 14. 主要风险与对策

### 14.1 孩子沉迷风险

对策：

- 单次任务封闭。
- 每日时长上限。
- 无排行榜。
- 无抽卡。
- 无无限聊天。
- 奖励绑定真实思考行为。

### 14.2 AI 陪伴依赖风险

对策：

- NPC 不声称真实情感。
- 不做“永远陪你”的表达。
- 不做情感关系养成。
- 对话围绕任务。
- 敏感情绪转向家长支持。

### 14.3 生成内容不可控

对策：

- 结构化输出。
- Schema 校验。
- 白名单素材。
- 安全规则引擎。
- 失败回退到固定模板。

### 14.4 语音识别不准

对策：

- 展示实时字幕让孩子确认。
- 关键任务允许点选修正。
- 保留文字输入备用。
- 针对游戏词汇做热词优化。

### 14.5 Minecraft 品牌风险

对策：

- 不使用 Minecraft 作为产品主名称。
- 不使用官方 Logo、材质、角色、音效。
- 做原创方块沙盒风格。
- 如后续联动 Minecraft Education，按官方规范和授权边界处理。

## 16. 最小可行产品定义

第一版产品可以收敛为：

> 孩子每天进入一个原创方块世界任务，用语音回答 NPC 的问题。系统实时把回答转成方块地图、建筑蓝图、材料背包和追问卡。每次任务最多 10-15 分钟，每周完成一个大工程，家长只看一页成长报告。

最小闭环：

```text
孩子愿意说
→ 系统听得懂
→ 地图能变化
→ NPC 能追问
→ 孩子能补充解释
→ 产品能记录能力
→ 家长能看见成长
```

只要这个闭环成立，产品就有继续扩展到 3D、更多项目、家庭订阅和 Minecraft Education 联动的基础。
