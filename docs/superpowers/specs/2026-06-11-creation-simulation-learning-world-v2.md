## 0. 核心结论

上一版“动态学习世界”的方向比“语音生成简笔画”更接近目标，但趣味性仍然不足，因为它仍然容易变成：

```text
世界包装下的学习任务
```

v2 应改成：

```text
AI 引导创作驱动的模拟测试学习世界
```

产品主循环：

```text
AI 给出兴趣化创作引导，或接住孩子自己的想法
→ 系统陪孩子画出结构设计
→ 系统把造物放进持续存在的交互世界
→ 造物与地形、环境、NPC 或其他旧造物发生作用
→ 交互因为孩子的认知不完整而出现真实后果
→ AI 和孩子一起分析原因
→ 孩子改装设计
→ 再次测试
→ 世界保存作品、测试、失败、改进和复盘
```

这才符合 8 岁孩子的真实状态：

```text
很多时候孩子不知道要创造什么
但只要 AI 给出足够有趣的起点，他就愿意继续造、测试、失败、改进
```

学习在这个过程中自然发生：

- 数学：重量、尺寸、比例、速度、资源、路径、成本。
- 科学：摩擦、压强、重心、材料、力、能量、电、天气、生态。
- 信息理解：读测试报告、地图、说明、数据、失败原因。
- 表达写作：讲设计、写改装日志、解释为什么这样改。
- 元认知：第一次为什么失败？我改了什么？下一次怎么试？
- AI 素养：AI 给的建议是否可靠？要不要测试验证？

## 1. 第一性需求重写

### 1.1 孩子的第一性需求

孩子不是想“被培养能力”，也不是想“完成每日任务”。但 8 岁孩子的自主选题能力通常还不稳定：有时能主动说出想造什么，有时只会说“随便”“不知道”，或者重复最近喜欢的一个主题。

所以产品不能只等孩子主动选题。孩子真正需要的是：

- AI 给我一个我感兴趣的创作起点。
- 这个起点和我喜欢的东西有关。
- 我能很快做第一个选择。
- 我想看到它真的动起来、跑起来、试起来。
- 我想知道它厉不厉害。
- 它失败了，我想让它变强。
- 我想把我的改进给别人看。

所以产品必须从“兴趣 + 引导”出发：

```text
你想自己造，还是从今天的挑战里选一个？
```

而不是：

```text
你今天要学习什么？
```

### 1.2 家长的第一性需求

家长希望孩子的兴趣不是空耗，而是转成能力：

- 喜欢画坦克、基地、飞船、机关、机器人这类造物，这些兴趣能不能被转成工程和科学学习？
- 喜欢和 AI 聊游戏，能不能从空聊变成结构化思考？
- 没时间陪学，产品能不能让孩子独立完成探索？
- 不希望产品变成沉迷游戏，也不希望 AI 替孩子思考。

### 1.3 产品第一性需求

产品要做到：

```text
兴趣先行
AI 给脚手架
孩子做选择
创作开始
模拟检验
失败有因
改进有路
学习自然发生
过程可回放
家长能看见成长
```

## 2. 一句话定位

> 一个面向儿童的“AI 引导创作-交互模拟-改装”动态学习世界。AI 根据孩子兴趣和能力短板给出创作挑战，孩子做选择并参与设计，系统用 Excalidraw 生成可编辑矢量结构图，再放入持续存在的可交互世界。孩子的造物会和地形、环境、NPC、材料、任务和其他旧造物发生作用；AI 判断哪些交互可以引出数学、科学、工程、信息理解、表达写作、元认知和 AI 素养，并把结果转成可解释的失败、改进和成长记录。

## 3. 产品形态

### 3.1 世界不再硬派任务，而是给创作脚手架

入口不能只问开放问题，因为孩子可能不知道怎么开始。推荐三入口：

```text
1. 我有自己的想法
2. 给我一个挑战
3. 继续升级上次的作品
```

如果孩子选择“我有自己的想法”，系统接住：

```text
你想造什么？它要完成什么挑战？
```

如果孩子选择“给我一个挑战”，AI 给 2-3 个兴趣化创作卡：

```text
今天的挑战：
1. 造一辆能过泥地的探险车
2. 造一个不会被大风吹倒的塔
3. 造一个能把水送到农田的装置
```

如果孩子选择“继续升级”，系统拿出旧作品：

```text
你的履带车上次通过了泥地，但在坡道上太慢。今天要不要升级它？
```

这三个入口都进入同一个创作-测试-改装循环。

### 3.2 设计不是画画，而是结构表达

Excalidraw 的作用是把孩子的想法变成可编辑结构图：

- 主体。
- 轮子/履带/腿/翅膀/推进器。
- 能源。
- 装甲/外壳/材料。
- 载重。
- 路线。
- 功能区。
- 风险点。

系统生成的是“工程草图”，不是艺术插画。

### 3.3 交互才是趣味核心

孩子的作品不能只是进入一次测试场，而要进入一个持续存在的交互世界。这个世界里有孩子过去造过的车、桥、基地、机器人、机关、道路、材料仓库和测试场。新造物可以和旧造物、地形、天气、NPC 任务发生作用。

交互来源有两种：

1. AI 推荐交互  
   AI 根据当前造物、旧造物和能力目标提出 2-3 个值得尝试的交互。

   ```text
   你的新履带车要不要：
   1. 去泥地救上次卡住的小车
   2. 拉材料去修桥
   3. 爬坡给山顶基地送电池
   ```

2. 孩子想象交互  
   孩子可以自己说：

   ```text
   我想让这个机器人坐上我的车去基地。
   我想让飞船把桥吊起来。
   我想让自动门接到太阳能电池。
   ```

AI 的任务不是简单说“可以/不可以”，而是判断这个交互能否安全、适龄、可模拟，并且能否引出学习点：

```text
可以直接模拟
→ 缺少条件，先问一个问题
→ 转成安全的等价测试
→ 没有明显学习价值，但可以作为纯世界互动保存
→ 不安全或不适龄，拒绝并换成安全挑战
```

测试结果不能只是“成功/失败”，而要有戏剧化但可解释的后果：

```text
车轮陷进泥地。
桥被压弯。
车身太高转弯翻倒。
电量不够，中途停下。
装甲太重，速度变慢。
履带通过泥地，但在石路上速度下降。
```

## 4. 核心循环

### 4.1 完整循环

```text
Guide：AI 给出创作脚手架，或接住孩子自己的想法
→ Choose：孩子做一个简单选择
→ Create：孩子参与创作
→ Draw：AI 与孩子一起画出结构
→ Interact/Simulate：放进交互世界，选择第一个互动
→ Fail/Consequence：产生可解释后果
→ Diagnose：孩子分析原因
→ Learn：系统补充必要知识
→ Upgrade：孩子改装
→ Retest：再次测试
→ Reflect：复盘
→ Persist：保存到长期世界
```

### 4.2 单次 10-15 分钟体验

```text
第 1 分钟：AI 给 2-3 个创作挑战，或孩子说自己的想法
第 2 分钟：孩子选择目标和第一个互动
第 3-5 分钟：系统画初版设计，孩子补一个关键部件
第 5-7 分钟：进入交互世界，出现问题
第 8-10 分钟：分析失败原因
第 11-13 分钟：选择一个改装
第 14-15 分钟：再次测试并保存改装日志
```

### 4.3 每周体验

每周围绕一个作品持续迭代：

```text
周一：初版设计
周二：泥地测试
周三：坡道测试
周四：载重测试
周五：能源测试
周六：综合挑战
周日：回放进化史 + 家长报告
```

## 5. 坦克/工程战车案例

### 5.1 安全定位

孩子可以喜欢“坦克大战”这种游戏主题，但产品里不做真实武器教学。建议统一包装为：

```text
卡通工程战车 / 履带探险车 / 防御车
```

重点放在：

- 移动方式。
- 地形适应。
- 重量。
- 稳定性。
- 材料。
- 能量。
- 结构取舍。

不涉及：

- 真实武器制造。
- 火力参数。
- 伤害细节。
- 现实攻击策略。

### 5.2 初版创作

孩子说：

```text
我要画一个很厉害的卡通履带车，用汽车轮子，很大的旋转塔，很厚的外壳。
```

系统生成结构图：

- 车身。
- 四个汽车轮。
- 旋转塔以“观察台/工具塔”表现。
- 厚外壳。
- 能量核心。
- 测试目标：穿过泥地。

AI 追问：

```text
它要先通过哪种地方？泥地、斜坡、石头路，还是桥？
```

### 5.3 第一次模拟失败

孩子选择泥地。

模拟结果：

```text
车开进泥地
→ 轮子陷进去
→ 车身越来越慢
→ 最后卡住
→ 旁边的测试车绕过去
```

系统不嘲笑，也不直接讲课，而是问：

```text
你觉得它为什么陷住了？
1. 车太重
2. 轮子接触地面太少
3. 泥地太软
4. 轮子太窄
```

### 5.4 学习自然出现

孩子选“轮子太窄”或“车太重”后，系统补充：

```text
在软地上，接触地面的面积越大，压力越分散，越不容易陷进去。
```

这里自然引出：

- 压强。
- 接触面积。
- 重量。
- 摩擦。
- 材料。
- 地形。

不需要先讲公式。8 岁孩子先理解现象即可。

### 5.5 改装

改装选项：

```text
1. 换成宽履带：更不容易陷，但速度变慢。
2. 减少装甲：更轻更快，但防护下降。
3. 换路线：绕过泥地，但路程变长。
4. 加宽轮胎：比原来好，但不如履带稳定。
```

每个改装对应一个知识点：

- 履带：接触面积、压强。
- 减重：重量和速度。
- 换路线：路径和时间。
- 宽轮胎：结构改良和取舍。

### 5.6 第二次测试

孩子选择履带。

模拟结果：

```text
履带车重新进入泥地
→ 下陷变少
→ 成功通过
→ 但速度比石路慢
```

系统问：

```text
这次为什么成功了？它又牺牲了什么？
```

这一步训练：

- 因果解释。
- 取舍意识。
- 复盘。
- 工程思维。

### 5.7 保存为成长记录

系统保存：

```text
作品：泥地履带战车
失败原因：汽车轮接触面积小，泥地中容易下陷
改进方案：换成履带
学到的点：接触面积、压强、重量、速度取舍
孩子原话：它变稳了，但是慢了
```

## 6. 新底层模块

### 6.1 Inspiration & Scaffolding Engine

负责在孩子自主性不足时启动创作。

输入：

- 孩子最近喜欢的主题。
- 历史作品。
- 最近薄弱能力。
- 今日可用时长。
- 家长设置的能力方向。

输出：

- 2-3 个创作挑战卡。
- 一个推荐继续升级的旧作品。
- 一个极低门槛的第一步选择。

示例：

```json
{
  "recommendedPrompts": [
    {
      "promptId": "mud_vehicle_challenge",
      "title": "造一辆能过泥地的探险车",
      "interestHook": "像你喜欢的战车，但今天重点是过泥地",
      "targetSkills": ["scientific_reasoning", "math_modeling"],
      "firstChoice": "轮子 / 履带 / 大脚"
    },
    {
      "promptId": "wind_tower_challenge",
      "title": "造一个不会被大风吹倒的塔",
      "targetSkills": ["stability", "center_of_gravity"],
      "firstChoice": "高塔 / 宽塔 / 三角支架"
    }
  ],
  "continueOption": {
    "creationId": "creation_vehicle_001",
    "nextTest": "slope_climb"
  }
}
```

### 6.2 Ability Gap Recommender

负责把能力短板转成有趣创作挑战。

例子：

```text
孩子最近很少做数量估算
→ 推荐“给探险车算电池能跑多远”

孩子最近不太会解释原因
→ 推荐“测试失败后选择一个原因并说为什么”

孩子最近科学观察少
→ 推荐“不同地形测试：泥地、石路、坡道”
```

这层不直接告诉孩子“你要补数学”，而是把短板包装成世界挑战。

### 6.3 Creation Engine

负责理解孩子在脚手架下选择或表达的创作意图。

输入：

- 语音。
- 手动画布。
- 选择的主题。
- AI 推荐的挑战卡。

输出：

- 作品类型。
- 部件列表。
- 功能目标。
- 测试场景建议。

示例：

```json
{
  "creationType": "cartoon_engineering_vehicle",
  "parts": ["body", "wheels", "turret_shape", "armor", "energy_core"],
  "goal": "cross_mud",
  "riskCandidates": ["too_heavy", "low_contact_area", "high_center_of_gravity"]
}
```

### 6.4 Design Canvas Compiler

负责把 Creation Engine 的结构结果编译成 Excalidraw elements。

职责：

- 生成可编辑结构图。
- 保持儿童能看懂的简洁视觉。
- 给部件加标签。
- 标出风险点。
- 支持孩子拖动、删除、改装。

### 6.5 Simulation Rules Engine

负责“作品放进世界后会发生什么”。

MVP 规则不需要真实物理引擎，但要符合直觉和基础科学。

规则类别：

- 地形：泥地、沙地、冰面、石路、坡道、桥。
- 移动：轮子、履带、腿、翅膀、推进器。
- 重量：装甲、载货、电池。
- 接触面积：轮胎宽度、履带宽度。
- 稳定性：重心、宽度、高度。
- 能源：电池、燃料、太阳能。
- 材料：木、石、金属、橡胶、玻璃。

### 6.6 Interactive World Engine

负责让孩子所有造物在同一个持续世界中共存和互动。

职责：

- 保存所有造物的位置、状态、能力、限制和历史版本。
- 支持新造物与旧造物、地形、天气、NPC、材料、路线、能源发生作用。
- 维护世界对象之间的连接关系，例如“车可以拉材料”“桥可以承重”“太阳能板可以给门供电”。
- 支持孩子自己提出交互想象。
- 支持 AI 根据学习目标推荐交互。

示例：

```text
履带车 + 泥地 → 测试接触面积和通过性
履带车 + 材料车厢 → 测试载重和速度
履带车 + 桥 → 测试重量和桥梁承重
太阳能板 + 自动门 → 测试能源和电路
机器人 + 山路 → 测试稳定性和路径规划
水泵 + 农田 → 测试水流方向和距离
```

### 6.7 Affordance Graph

负责描述每个造物“能和什么互动”。

每个造物不只是图形，而是有能力和限制：

```text
能移动
能承重
能供电
能储物
能拉动
能浮在水上
能通过窄路
怕水
太重
重心高
需要电池
```

AI 推荐或判断交互时，不直接看画面，而是看 Affordance Graph：

```text
对象 A 有 carry 能力
对象 B 有 heavy 属性
地形是 slope
→ 可以生成“载重爬坡测试”
→ 学习点：重量、摩擦、能量、坡度
```

### 6.8 Interaction Orchestrator

负责处理孩子或 AI 提出的交互请求。

输入：

- 当前造物。
- 世界中可互动对象。
- 孩子的想象表达。
- 当前能力目标。
- 安全策略。

输出：

```text
simulate_now：可以直接模拟
ask_clarifying_question：缺少关键条件，先问孩子
suggest_safer_variant：转成安全等价测试
save_as_playful_interaction：可玩但学习价值低，保存为世界互动
decline_and_redirect：不安全或不适龄，拒绝并换成安全挑战
```

例子：

```text
孩子：我想让飞船把桥吊起来。
AI 判断：可以转成“吊装测试”。
需要追问：飞船用什么把桥吊起来？绳子、磁铁，还是机械臂？
学习点：重量、拉力、稳定性、材料强度。
```

### 6.9 Learning Opportunity Detector

负责判断一个交互是否值得作为学习事件。

评分维度：

- 是否有可观察后果。
- 是否能引出数学、科学、工程或信息理解。
- 是否需要孩子做一个判断或取舍。
- 是否能连接孩子已有兴趣。
- 是否安全、适龄、不过度刺激。

如果学习价值高，进入完整闭环：

```text
交互 → 模拟 → 后果 → 分析 → 改装 → 再测试 → 复盘
```

如果学习价值低，可以允许轻互动，但不把它作为主要学习记录。

### 6.10 Failure & Consequence Engine

负责生成有趣但可解释的失败。

原则：

- 失败指向认知缺口，不指向孩子不好。
- 失败要可视化。
- 失败后必须能改。
- 每次只暴露 1-2 个主要原因，避免过载。

失败类型：

- 卡住。
- 翻倒。
- 断裂。
- 过热。
- 没电。
- 太慢。
- 路线太长。
- 材料不够。
- 结构不稳。

### 6.11 Upgrade Workshop

负责给孩子改装空间。

不是给标准答案，而是给取舍：

```text
换履带：稳定，但慢。
减重：快，但防护少。
加宽底盘：稳，但材料多。
换路线：安全，但时间长。
```

孩子必须说出理由：

```text
我选择履带，因为泥地软，需要更大的接触面积。
```

### 6.12 Learning Moment Engine

负责在孩子“想知道为什么”的时候给最少必要知识。

原则：

- 不在测试前上课。
- 失败后再解释。
- 只解释当前问题需要的知识。
- 用图和现象解释，不先给公式。

### 6.13 World Persistence Engine

负责把作品放入长期世界。

保存：

- 作品初版。
- 造物在世界中的位置和状态。
- 与其他造物的交互历史。
- 测试场景。
- 失败结果。
- 改装版本。
- 孩子解释。
- 学习点。
- 回放时间线。

## 9. 趣味性设计原则

### 9.1 兴趣先于学习

系统不问：

```text
今天要学压强吗？
```

系统问：

```text
你的车要不要挑战泥地？
```

### 9.2 失败先于讲解

不要先讲：

```text
履带可以增大接触面积。
```

而是先让孩子看到：

```text
汽车轮陷进泥地。
```

孩子有困惑后，再解释。

### 9.3 取舍比标准答案更重要

工程没有唯一正确答案。产品要让孩子感到：

```text
每个改装都有代价。
```

这样才能训练分析思维。

### 9.4 孩子拥有作品

作品必须长期存在：

- 我的第一辆车。
- 第二版履带车。
- 第三版轻量车。
- 泥地测试冠军。
- 坡道失败版本。

孩子回来不是为了打卡，而是为了继续升级自己的东西。

### 9.5 戏剧性后果，但不羞辱

失败要有趣：

```text
车轮咕嘟咕嘟陷进泥里。
工程师 NPC 说：我们找到问题了，不是你不行，是设计还没适应泥地。
```

失败不能说：

```text
你错了。
```

## 10. 学习能力如何自然发生

### 10.1 数学建模

来自：

- 车身多长。
- 履带多宽。
- 装甲多重。
- 需要多少材料。
- 路线多远。
- 电池能跑多久。
- 改装成本够不够。

### 10.2 科学探究

来自：

- 为什么陷进泥地。
- 为什么坡上打滑。
- 为什么太高会翻。
- 为什么桥被压弯。
- 为什么电池不够。
- 为什么不同材料表现不同。

### 10.3 信息理解

来自：

- 测试报告。
- 地形说明。
- 材料卡。
- 失败原因提示。
- AI 建议。
- 地图和路线数据。

### 10.4 表达写作

来自：

- 设计说明。
- 改装理由。
- 测试日志。
- 失败复盘。
- 给 NPC 的改进报告。

### 10.5 元认知

来自：

```text
我原来怎么想？
测试发生了什么？
哪里和我想的不一样？
我改了什么？
下一次怎么试？
```

### 10.6 AI 素养

AI 可以故意给一个不完整建议：

```text
把装甲加厚就一定更厉害。
```

孩子通过测试发现：

```text
装甲厚了，但车太重，过不了桥。
```

这比说教更能让孩子理解：

```text
AI 的建议要验证。
```

## 11. 世界结构

### 11.1 主世界

主世界不再是“学习区集合”，而是“可交互创作沙盒”。孩子所有造物都会留在这个世界里，之后的新挑战可以调用旧造物、旧失败、旧改装经验。

建议区域：

1. 创作工坊
   - 选择挑战、说出想法、继续旧作品，生成设计。

2. 测试场
   - 泥地、坡道、冰面、桥、沙地、山路。

3. 互动沙盒
   - 让车、桥、基地、机器人、能源装置、材料车、农田、水泵等互相作用。

4. 改装车间
   - 换部件、减重、加固、改能源。

5. 材料仓库
   - 木、金属、橡胶、玻璃、电池、太阳能板等。

6. 实验室
   - 观察、假设、测试、记录。

7. 知识中心
   - 测试报告、材料说明、地图、AI 建议验证。

8. 回放馆
   - 看作品从初版到改进版的进化史。

### 11.2 世界长期变化

孩子每完成一轮迭代，世界会保存：

- 新作品。
- 新部件。
- 新测试场。
- 新互动关系。
- 新失败案例。
- 新改装经验。
- 新知识卡。

例如：

```text
通过泥地测试 → 解锁沼泽区域
完成坡道测试 → 解锁山地测试场
发现 AI 建议错误 → AI 工坊升级
完成三次复盘 → 回放馆新增“进化史展台”
```

## 12. Excalidraw 的角色

Excalidraw 仍然适合，但角色要更精确。

负责：

- 创作草图。
- 结构图。
- 部件标注。
- 改装前后对比。
- 测试过程中的关键帧。
- 回放中的矢量场景。

不负责：

- 真实物理模拟。
- 世界状态。
- 学习评估。
- 失败判断。
- 创作引导逻辑。

正确关系：

```text
CreationSpec / WorldState / SimulationResult
→ Scene Compiler
→ Excalidraw Elements
```

不是：

```text
Excalidraw Elements
→ 反推学习和世界状态
```

## 13. MVP 范围

### 13.1 MVP 只做一个强闭环

建议 MVP 只做：

```text
卡通工程战车
+ 泥地测试
+ 拉材料去修桥的互动
+ 改装履带
+ 再测试
+ 保存回放
```

不要一开始做太多世界、创作类型和任务。

MVP 核心验收：

- 孩子能在 AI 引导下选择一个创作挑战，或说出自己的想法。
- 系统能画出结构图。
- 系统能让初版在测试中失败。
- 孩子愿意分析失败原因。
- 孩子愿意改装。
- 第二次测试能体现改装效果。
- 家长能看懂这是科学/工程学习，不是普通画画或聊天。

### 13.2 MVP 必须有

- 语音输入。
- 2-3 张 AI 创作挑战卡。
- 一个“继续升级上次作品”入口。
- Excalidraw 结构草图。
- 一个测试场：泥地。
- 一个旧世界对象：断桥。
- 一个可互动对象：材料车。
- 两种移动部件：轮子、履带。
- 三个物理直觉规则：重量、接触面积、速度。
- 一个交互判断：能否拉材料穿过泥地去修桥。
- 一个失败动画：陷住。
- 一个改装选择：换履带或减重。
- 一段回放。
- 一条成长记录。

### 13.3 MVP 暂不做

- 多种创作类型。
- 真实战斗。
- 武器细节。
- 完整 3D。
- 多人。
- 社区。
- 排行榜。
- 商城。
- 大量课程。

## 14. 关键指标

孩子侧：

- 是否愿意从 AI 创作挑战卡中选择一个方向。
- 是否愿意补充一个自己的设计选择。
- 是否愿意看测试结果。
- 是否愿意尝试 AI 推荐交互。
- 是否愿意提出自己的交互想象。
- 失败后是否愿意再试一次。
- 单次改装完成率。
- 回放观看率。

学习侧：

- 是否能说出失败原因。
- 是否能说出改装理由。
- 是否能理解至少一个取舍。
- 是否能理解一个交互带来的因果关系。
- 是否能完成一次复盘表达。

家长侧：

- 是否认为孩子在玩中学到了工程/科学。
- 是否认为产品比普通 AI 聊天更有价值。
- 是否愿意让孩子连续使用一周。

北极星指标：

```text
每周完成的“创作-交互-测试-改装-复盘”闭环数
```

## 15. 风险与边界

### 15.1 战斗主题风险

孩子可能喜欢坦克、战斗、防御。

处理：

- 可以保留卡通工程车、履带车、防御挑战、障碍测试。
- 不做真实武器制造。
- 不强调伤害。
- 不讲攻击细节。
- 把对抗改成测试、穿越、救援、运输、防护、障碍挑战。

### 15.2 模拟太复杂

对策：

- MVP 用规则模拟，不用真实物理引擎。
- 每次只测试一个主要变量。
- 失败原因最多 1-2 个。

### 15.3 孩子不知道造什么

对策：

- 默认提供 2-3 张创作挑战卡。
- 每张卡只要求一个第一选择，例如轮子/履带/大脚。
- 提供“继续升级上次作品”作为低成本入口。
- AI 根据历史兴趣和能力短板推荐，不让孩子面对空白画布。

### 15.4 学习点太硬

对策：

- 失败后才解释。
- 每次只讲当前改装需要的知识。
- 用现象和图解释，不先上公式。

### 15.5 孩子只想赢，不想复盘

对策：

- 改装必须说一句理由才能测试。
- 复盘非常短，只问一个问题：

```text
这次你改了什么？为什么？
```

### 15.6 家长担心玩物丧志

对策：

- 家长报告直接展示学习证据：

```text
本周孩子通过泥地测试理解了“接触面积影响下陷”。
他说：“履带更稳，但是慢。”
这体现了因果解释和工程取舍。
```

## 16. 推荐路线图

### 阶段 1：单闭环原型，1-2 周

做一个完整体验：

```text
AI 给出“造一辆能过泥地的探险车”挑战
→ 孩子选择轮子
→ 画轮子车
→ AI 推荐“拉材料去修桥”
→ 轮子车拉材料穿过泥地失败
→ 解释失败
→ 换履带
→ 再次拉材料成功
→ 保存回放
```

### 阶段 2：MVP，4-6 周

扩展到：

- 3 个测试场：泥地、坡道、桥。
- 3 类互动对象：材料车、桥、能源装置。
- 4 个部件：轮子、履带、装甲、电池。
- 5 个失败原因：陷住、翻倒、压弯、太慢、没电。
- 10 个创作模板。

### 阶段 3：内测，8-12 周

扩展到：

- 多种创作：车辆、基地、飞船、机器人、机关。
- 每个创作都有测试场和可互动对象。
- 长期世界和作品库。
- 造物之间的互动历史。
- 家长周报。
- AI 建议验证。

## 17. 最终判断

最能激发孩子的产品不是“动态学习世界给任务”，而是：

```text
AI 给出有趣创作脚手架
→ 孩子做选择并参与造物
→ 世界让造物与环境、NPC 和旧造物互动
→ 失败制造好奇
→ 分析带出知识
→ 改装形成掌控
→ 回放沉淀成长
```

这条路线更适合 8 岁孩子，因为它不要求孩子一开始就有完整创意，而是用 AI 提供的挑战卡和旧作品升级入口降低启动成本，同时保留孩子的选择权、掌控感和好奇心。学习不是前置任务，而是让自己的作品变得更厉害、更合理、更能适应世界的必要工具。

Excalidraw 在这里仍然有价值，但它只负责“设计图和关键帧表现”。真正的核心是：

```text
Inspiration & Scaffolding Engine
+ Ability Gap Recommender
+ Creation Engine
+ Interactive World Engine
+ Affordance Graph
+ Interaction Orchestrator
+ Learning Opportunity Detector
+ Simulation Rules Engine
+ Failure & Consequence Engine
+ Upgrade Workshop
+ Learning Moment Engine
+ World Persistence Engine
```
