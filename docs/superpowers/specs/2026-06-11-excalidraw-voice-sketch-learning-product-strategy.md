## 0. 规划结论

这个产品的第一性需求不是“生成图”，也不是“做一个儿童版 Excalidraw”。真正需求是：

> 孩子把脑子里的想法说出来，系统立刻把想法画成能看见、能修改、能回放的简笔画过程，并用追问引导孩子解释、比较、改进和复盘。

因此，最优方案不是重型游戏引擎，也不是 AI 图片生成，而是：

```text
语音表达
→ AI 理解想法和学习目标
→ 生成结构化 Sketch DSL
→ 编译成 Excalidraw elements
→ 分步写入画布形成简笔画动画
→ 孩子继续解释和修改
→ 保存为矢量场景 + 事件时间线
→ 支持回放孩子从想法到作品的思考过程
```

产品一句话：

> 一个给孩子独立使用的“会画画的思维采访官”：孩子说，系统画；系统画，孩子解释；孩子解释后，系统追问和记录成长。

第一版不应追求完整 Minecraft 风格游戏，而应借用孩子喜欢的“方块、基地、红石、村庄、冒险”主题，用 Excalidraw 简笔画把这些兴趣转成表达、逻辑、规划和复盘训练。

## 2. 第一性需求

### 2.1 孩子的真实需求

孩子不是想“学习未来能力”。孩子真实想要的是：

- 把自己喜欢的世界讲出来。
- 看到自己的想法马上变成画面。
- 能控制画面继续变化。
- 能讲给别人听。
- 能被认真追问，而不是被考试。
- 能完成一个看得见的作品。

因此产品必须满足：

```text
低门槛表达
+ 及时可视反馈
+ 自主控制感
+ 有趣主题
+ 不像上课
+ 能留下作品
```

### 2.2 家长的真实需求

家长不是想每天陪孩子学习，也不是想看复杂数据。家长想要的是：

- 孩子少刷无意义短视频或空聊。
- 孩子能独立使用。
- 兴趣没有浪费，能转成能力。
- 产品安全，不让孩子沉迷或依赖 AI。
- 每周能看见孩子是否真的有进步。

因此产品必须满足：

```text
孩子独立使用
+ 家长低负担查看
+ 内容安全
+ 成长可见
+ 不做开放式陪伴聊天
```

### 2.3 学习的真实需求

未来能力不是靠听讲获得，而是靠反复经历以下循环获得：

```text
表达想法
→ 看见想法
→ 解释理由
→ 发现漏洞
→ 修改方案
→ 形成作品
→ 复盘过程
```

Excalidraw 的价值在于：它能把这个循环变成可视、可编辑、可保存、可回放的矢量过程。

### 2.4 AI 的真实角色

AI 不应是：

- 替孩子回答问题的人。
- 开放式聊天朋友。
- 情绪陪伴对象。
- 生成漂亮图片的魔法按钮。

AI 应是：

- 语音理解器。
- 简笔画生成器。
- 追问者。
- 反方挑战者。
- 复盘记录员。
- 成长观察员。

## 3. 产品愿景

### 3.1 Vision

让孩子把想法说出来、画出来、改出来、讲出来，长期形成独立思考和表达的能力。

### 3.2 价值观

- 孩子先想，AI 后画。
- AI 只辅助表达，不替代思考。
- 每次使用都留下可回放的思考过程。
- 作品比打卡重要。
- 复盘比评分重要。
- 安全边界比开放聊天重要。

### 3.3 北极星体验

孩子说：

```text
我想建一个山上的秘密基地，有电梯、仓库和防御机关。
```

系统几秒内画出：

- 一座山。
- 山顶基地。
- 电梯线。
- 仓库方框。
- 防御标记。
- 材料图标。
- NPC 问题卡。

然后问：

```text
你为什么把仓库放在基地里面？
如果电梯坏了，还有备用路线吗？
```

孩子继续说，画面继续变化。最后可以回放：

```text
第 1 步：孩子提出秘密基地。
第 2 步：系统画出山和基地。
第 3 步：孩子解释仓库位置。
第 4 步：系统加入备用路线。
第 5 步：孩子复盘下一版要改什么。
```

这就是产品核心。

## 7. Excalidraw 底座定位

### 7.1 Excalidraw 适合做什么

Excalidraw 适合作为：

- 矢量画布。
- 简笔画风格输出。
- 可编辑作品存档。
- 可导出 SVG/PNG 的作品。
- 可通过 API 更新场景的画布。
- 可回放的场景状态载体。
- 儿童表达过程的视觉记录。

官方文档显示，Excalidraw 场景使用 plaintext JSON，`.excalidraw` 文件包含 `type`、`version`、`source`、`elements`、`appState`、`files` 等字段；React 组件可通过 `@excalidraw/excalidraw` 集成；`excalidrawAPI.updateScene` 可更新场景；`onChange` 可订阅 elements/appState/files 变化；export utilities 支持导出 canvas、blob、SVG。

### 7.2 Excalidraw 不适合做什么

不适合作为：

- 完整游戏引擎。
- 高帧率角色动画引擎。
- 复杂碰撞和物理系统。
- 真实 Minecraft 3D 世界。
- 长时间沉浸式游戏。

因此产品要把 Excalidraw 用在最擅长的地方：

```text
画布 + 结构化图形 + 时间线 + 回放 + 存档
```

而不是强行把它做成游戏。

### 7.3 产品中的 Excalidraw 角色

```text
Excalidraw = 孩子想法的可视化纸面
```

它承载：

- 当前任务图。
- 孩子设计的结构。
- AI 追问卡片。
- 修改痕迹。
- 作品回放。
- 成长档案。

## 8. 核心体验设计

### 8.1 场景：孩子讲一个基地

孩子说：

```text
我要做一个山上的基地，里面有仓库、电梯、观察台，还有一条逃生路。
```

系统生成动画：

```text
第 1 秒：画出山。
第 2 秒：画出山顶平台。
第 3 秒：画出基地外框。
第 4 秒：标出仓库。
第 5 秒：画出电梯线。
第 6 秒：画出观察台。
第 7 秒：用虚线画逃生路。
第 8 秒：弹出 NPC 追问卡。
```

NPC 追问：

```text
如果电梯坏了，逃生路够安全吗？
仓库为什么放在基地里面？
观察台能看到哪几个方向？
```

孩子补充后，画面继续改：

- 逃生路变粗。
- 加一个备用梯子。
- 观察台加视野扇形。
- 仓库旁边加防火标记。

### 8.2 体验关键

产品的爽点不是“画得多美”，而是：

```text
我一说，它就懂了。
我一解释，它就改了。
我一回放，就能看见我是怎么想出来的。
```

## 10. 关键功能

### 10.1 语音生成简笔画

流程：

```text
语音输入
→ 实时字幕
→ 意图识别
→ Sketch DSL
→ Excalidraw elements
→ 分步 updateScene
→ 动画化呈现
```

Sketch DSL 示例：

```json
{
  "sceneTitle": "山顶秘密基地",
  "learningGoals": ["planning", "risk_analysis", "explain_reason"],
  "frames": [
    {
      "at": 0,
      "action": "add",
      "objects": [
        {"type": "mountain", "label": "山", "x": 80, "y": 120}
      ]
    },
    {
      "at": 900,
      "action": "add",
      "objects": [
        {"type": "base", "label": "基地", "x": 180, "y": 80},
        {"type": "storage", "label": "仓库", "x": 210, "y": 120}
      ]
    },
    {
      "at": 1800,
      "action": "ask",
      "question": "你为什么把仓库放在基地里面？"
    }
  ]
}
```

系统不让 LLM 直接写复杂 Excalidraw JSON。推荐二段式：

```text
LLM 生成 Sketch DSL
→ 程序把 Sketch DSL 编译成 Excalidraw elements
```

这样更稳定、更安全、更容易控制画风。

### 10.2 简笔画动画

Excalidraw 本身主要是静态画布，不是动画引擎。产品需要自己维护时间线。

动画实现分三层：

```text
Layer 1：事件时间线
- 每一步新增/修改/删除哪些对象
- 对应哪一句孩子语音
- 对应哪个 AI 追问

Layer 2：画布状态
- 每一步编译成 Excalidraw elements
- 使用 updateScene 写入

Layer 3：播放器
- 按时间顺序重放 scene patches
- 支持暂停、快进、回看某一句话
```

第一版不需要真正逐笔画线，可以采用“分步出现 + 轻微描边动效 + 视角移动”的方式，让孩子感觉是画出来的。

### 10.3 矢量存档

每个作品保存三个文件层：

```text
1. scene.excalidraw
   - 最终画布
   - elements/appState/files

2. timeline.json
   - 每一步动作
   - 时间戳
   - 语音转写
   - NPC 追问
   - 能力事件

3. summary.json
   - 今日成长点
   - 家长摘要
   - 下次建议
```

这比只保存一张图片更有价值，因为它保存了孩子的思考过程。

### 10.4 可回放

回放模式：

```text
作品回放：看图如何一步步生成。
思考回放：听孩子每一步说了什么。
复盘回放：看系统追问和孩子如何修改。
家长精选：压缩成 60 秒摘要。
```

回放不是娱乐功能，而是学习功能。它帮助孩子看见：

- 我一开始怎么想。
- 后来为什么改。
- 哪个问题让我想得更深。
- 下次可以怎么做更好。

### 10.5 NPC 追问

NPC 是产品中最重要的教学机制。

角色：

- 画图助手：把孩子说的话画出来。
- 结构工程师：追问规划和逻辑。
- 挑刺村民：问风险和反例。
- 记录员：引导复盘。
- 安全守卫：处理隐私和危险话题。

每次任务最多追问 2-3 轮。

### 10.6 作品库

作品不是普通图片列表，而是“成长档案”。

每个作品卡片显示：

- 标题。
- 主题。
- 最终画面缩略图。
- 回放时长。
- 训练能力。
- 孩子一句讲解。
- 家长摘要。

## 12. 产品策略画布

### 12.1 Vision

让孩子用语言创造画面，用画面推动思考，用回放看见成长。

### 12.2 Market Segments

第一细分市场：

```text
孩子喜欢 Minecraft/方块沙盒/AI 聊天，但家长希望把兴趣转成能力培养。
```

JTBD：

- 当孩子想聊游戏时，家长希望这个过程不只是空聊。
- 当孩子有很多想象时，家长希望他能讲清楚、画出来、复盘。
- 当家长没时间陪学时，希望产品能提供安全的结构化引导。

第二细分市场：

```text
重视表达、创造力和项目制学习的家庭。
```

第三细分市场：

```text
未来可扩展到教育机构的项目式学习辅助工具。
```

### 12.3 Relative Costs

不走低价工具路线。产品价值在于：

- 儿童适龄交互。
- 语音到矢量画布。
- 可回放思考过程。
- 家长低负担报告。
- 安全边界。

成本主要来自：

- ASR 语音识别。
- LLM 结构化生成。
- 存储和回放。
- 儿童安全审核。

### 12.4 Value Proposition

对孩子：

```text
以前：和 AI 聊游戏，聊完就没了。
现在：说出来就变成画，画还能继续改，最后变成作品。
```

对家长：

```text
以前：担心孩子沉迷 AI 或游戏空聊。
现在：孩子兴趣被转成表达、逻辑、规划和复盘训练。
```

对产品：

```text
普通 AI 聊天只有对话记录。
这个产品有矢量作品、过程回放和成长证据。
```

### 12.5 Trade-offs

明确不做：

- 不做开放式 AI 伙伴。
- 不做真实 Minecraft 复制品。
- 不做社交社区。
- 不做排行榜。
- 不做抽卡激励。
- 不做全学科题库。
- 不做高复杂 3D 游戏。
- 不在 MVP 做多人协作。

选择做：

- 语音表达。
- 简笔画自动生成。
- 结构化追问。
- 矢量存档。
- 可回放复盘。
- 家长周报。

### 12.6 Key Metrics

North Star Metric：

```text
每周完成并回放的高质量思考作品数
```

定义：

```text
高质量思考作品 = 有孩子语音表达 + 有画布生成 + 至少 1 次追问补充 + 有最终回放
```

第一季度 OMTM：

```text
7 天内完成 3 个以上每日作品的孩子比例
```

### 12.7 Growth

早期增长不靠广告投放，靠作品传播：

- 家长愿意保存孩子的 60 秒作品回放。
- 孩子愿意给家人展示。
- 家长在小范围社群分享“孩子说话变成画”的效果。

首批渠道：

- 家长社群。
- AI 教育内容号。
- Minecraft/编程启蒙兴趣家长。
- 项目式学习社群。

### 12.8 Capabilities

必须具备：

- 儿童语音理解。
- Sketch DSL 生成。
- Excalidraw elements 编译。
- 时间线回放。
- 儿童安全策略。
- 任务模板设计。
- 家长周报生成。

可外部采购：

- ASR。
- LLM。
- 基础云存储。

必须自研：

- Sketch DSL。
- 儿童任务体系。
- Excalidraw 动画时间线。
- 成长事件模型。
- 亲子报告表达。

### 12.9 Can't/Won't

壁垒来自：

- 不是单纯接一个模型，而是积累儿童表达到画布的 DSL。
- 每个作品有过程数据和成长事件。
- 任务体系越用越适合孩子。
- 家长报告建立长期信任。
- 安全边界和低沉迷设计形成差异化。

## 13. 技术架构

### 13.1 总体架构

```text
Child Web App
  - Voice Capture
  - Excalidraw Canvas
  - Timeline Player
  - Task UI

Backend Orchestrator
  - ASR Adapter
  - LLM Adapter
  - Sketch DSL Generator
  - Excalidraw Compiler
  - Safety Validator
  - Growth Event Extractor
  - Replay Packager
  - Parent Report Generator

Storage
  - child_profile
  - sketch_sessions
  - excalidraw_scenes
  - replay_timelines
  - transcript_summaries
  - growth_events
  - parent_reports
```

### 13.2 Excalidraw 集成方式

前端：

```text
@excalidraw/excalidraw
```

关键 API：

- `initialData`：加载作品。
- `excalidrawAPI.updateScene`：分步更新画布。
- `excalidrawAPI.getSceneElements`：读取当前元素。
- `excalidrawAPI.getAppState`：读取当前画布状态。
- `excalidrawAPI.getFiles`：读取图片文件数据。
- `onChange`：记录用户手动修改。
- `exportToSvg`：导出矢量作品。
- `exportToCanvas/exportToBlob`：生成缩略图或分享图。

### 13.3 Sketch DSL 到 Excalidraw Elements

不要让 LLM 直接控制每个 Excalidraw 字段。

推荐链路：

```text
LLM 输出 Sketch DSL
→ validateSketchPlan()
→ compileToExcalidrawElements()
→ scheduleTimelineFrames()
→ excalidrawAPI.updateScene()
```

元素编译规则：

- `mountain` 编译成三角形和线条。
- `base` 编译成矩形、屋顶、标签。
- `elevator` 编译成竖线和箭头。
- `risk` 编译成警示图标和文字卡。
- `question` 编译成 NPC 追问卡。

### 13.4 回放实现

不要依赖 Excalidraw 原生历史栈作为产品回放。

产品自己维护：

```json
{
  "sessionId": "s_001",
  "frames": [
    {
      "time": 0,
      "type": "speech",
      "transcript": "我要做一个山上的基地"
    },
    {
      "time": 600,
      "type": "scene_patch",
      "add": ["mountain_1", "base_1"]
    },
    {
      "time": 1800,
      "type": "npc_question",
      "text": "为什么基地要建在山上？"
    }
  ]
}
```

回放时按 frames 逐步调用 `updateScene`，或在独立播放器中渲染每一步。

### 13.5 存档格式

每个作品保存：

```text
final.excalidraw
timeline.json
transcript-summary.json
growth-events.json
thumbnail.svg
parent-summary.md
```

## 14. UI/UX 原则

### 14.1 儿童画布界面

界面分三块：

```text
左/中：Excalidraw 画布
右侧：NPC 追问卡
底部：按住说话 / 完成 / 回放
```

平板优先：

- 按钮不小于 44px。
- 字体不小于 16px。
- 一屏只显示一个主任务。
- 不显示复杂工具栏。
- Excalidraw 原生工具栏需要儿童化裁剪。

### 14.2 Excalidraw 工具裁剪

孩子第一版只需要：

- 选择/移动。
- 橡皮/删除。
- 画线。
- 箭头。
- 文字。
- 简单形状。
- 撤销/重做。

不需要：

- 复杂样式设置。
- 多人协作。
- 插入外部图片。
- 高级图层管理。
- 复杂导出入口。

### 14.3 动画原则

- 动画服务理解，不做纯装饰。
- 分步出现表达因果。
- 可以暂停和回放。
- 支持 reduced-motion。
- 不做高刺激动效。

## 15. 儿童安全与隐私

### 15.1 AI 边界

产品必须保持任务型 AI。

禁止：

- 情感依赖话术。
- 无限聊天。
- 成人话题。
- 暴力强化。
- 真实危险行为指导。
- 上传学校、地址、姓名等隐私。
- 让孩子把 AI 当朋友或权威。

### 15.2 数据最小化

默认不保存原始音频。

优先保存：

- 转写摘要。
- Excalidraw 场景。
- 回放时间线。
- 成长事件。
- 家长报告。

需要家长显式授权才保存：

- 原始语音。
- 图片文件。
- 长期完整转写。

### 15.3 安全触发

触发场景：

- 孩子说出姓名、学校、住址、电话。
- 长时间连续使用。
- 询问危险行为。
- 情绪风险。
- 让 AI 帮忙直接完成作业。

处理：

- 停止追问。
- 用安全守卫提示。
- 必要时建议找家长。
- 记录安全事件给家长摘要。

## 18. 关键假设与验证实验

### 18.1 假设 1：孩子愿意用语音驱动画面

实验：

- 做 5 个 Wizard-of-Oz 原型。
- 成人在后台快速把孩子语音转成简笔画。
- 观察孩子是否愿意继续说第二轮。

成功标准：

- 70% 以上孩子完成 2 轮以上补充表达。

### 18.2 假设 2：Excalidraw 简笔画足够吸引

实验：

- 对比 AI 图片、2D 方块图、Excalidraw 简笔画三种反馈。
- 看孩子是否愿意修改和回放。

成功标准：

- Excalidraw 版本的“修改次数”和“讲解意愿”不低于其他版本。

### 18.3 假设 3：回放能帮助复盘

实验：

- 一组只看最终图。
- 一组看生成过程回放。
- 比较孩子能否说出“我为什么修改”。

成功标准：

- 回放组能说出修改原因的比例明显更高。

### 18.4 假设 4：家长认可低负担周报

实验：

- 给 10 位家长看 1 分钟作品回放和一页周报。
- 问是否愿意让孩子每周使用。

成功标准：

- 60% 以上家长认为“比普通 AI 聊天更有价值”。

## 21. 风险与对策

### 21.1 Excalidraw 动画能力不足

风险：

- Excalidraw 不是动画引擎。

对策：

- 用自研 timeline 控制 `updateScene` 分步更新。
- MVP 使用分步出现，不做逐笔高帧率动画。
- 后续需要更强动画时，增加独立 replay renderer。

### 21.2 LLM 生成元素不稳定

风险：

- 直接让 LLM 写 Excalidraw JSON 容易出错。

对策：

- LLM 只写 Sketch DSL。
- 编译器负责生成 Excalidraw elements。
- Schema 校验和白名单素材。

### 21.3 孩子觉得不够像游戏

风险：

- 简笔画不如 Minecraft 刺激。

对策：

- 主题借用方块、基地、红石、冒险。
- 奖励是世界区域扩展和作品回放。
- 保持短任务、高反馈。

### 21.4 家长担心 AI 聊天

风险：

- 家长把产品误解成 AI 陪聊。

对策：

- 强调任务型 AI。
- 限制对话轮次。
- 提供安全报告。
- 默认不保存原始音频。

## 23. 最小可行产品定义

MVP 可以收敛成一句话：

> 孩子每天用语音讲一个自己喜欢的方块世界想法，系统把它画成 Excalidraw 简笔画动画，并通过 2 轮追问让孩子解释和修改，最后保存成可回放的矢量作品和一条成长记录。

最小闭环：

```text
孩子愿意说
→ 系统能画出来
→ 孩子愿意解释
→ 系统能改画
→ 孩子愿意回放
→ 家长能看见成长
```

这比单纯“语音生成图片”更接近第一性需求，因为它保存的不是结果图，而是孩子思考、表达、修改和复盘的完整过程。
