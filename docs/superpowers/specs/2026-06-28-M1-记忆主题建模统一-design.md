# M1 · 记忆↔主题建模统一(设计)

- 日期:2026-06-28 · 来源:P2b 数据审查报告 M1 项
- 结论:**大规模重构(10+ 消费点 + 数据迁移),非功能 bug(现状工作),应独立分阶段 TDD,不在审查修复批次内鲁莽合并。** 本文给出设计 + 影响面 + 分阶段 + 风险,供独立执行。

## 1. 现状:同一"X 属于主题 T"语义两套建模

| 资产 | 主题归属编码 | 元数据 |
|---|---|---|
| point/question/decision/debt/note/session/importSource | 内嵌 `relatedThemeIds: string[]`(P2c 已统一可空性) | 无边 id / 时间 |
| **memory** | 独立实体 `MemoryEdge { id?, fromMemoryRecordId, themeId, createdAt? }`(`state.memoryEdges[]`) | 有边 id / createdAt |

SurrealDB 边投影:七类 `relatedThemeIds` → `belongs_to_theme`;memory `memoryEdges` → `about_theme`(edge-mapper.ts ① vs ③ 两段)。`recallThemeAssets` 因此维护两条对称但分裂的图遍历路径(`<-belongs_to_theme<-point/decision/question` + `<-about_theme<-memory`)。

## 2. 目标

MemoryRecord 收编 `relatedThemeIds`,`MemoryEdge` 退役;记忆↔主题与七类资产统一为内嵌 `relatedThemeIds` + 统一边投影(均走 belongs_to_theme 或保留 about_theme 但投影自 record.relatedThemeIds)。消除"两套建模 + 两条召回路径"。

## 3. 影响面(grep 实测 10+ 消费点)

- `types.ts`:MemoryRecord 加 `relatedThemeIds`;`MemoryEdge` / `ProductState.memoryEdges` 退役(分阶段)。
- `memory.ts`:`approveMemoryCandidate`(生成 memoryEdges→改填 record.relatedThemeIds)、`updateMemoryRecordText`(filter/rebuild memoryEdges→改 record.relatedThemeIds)、`buildMemoryEdgesForRecord`(返回 themeIds 填 record)。
- `context-pack.ts`:`buildMemoryEdgesForRecord`、`buildContextPackMemoryEdges`、`buildMemoryGraphReferences`、contextPack.memoryEdges 输出 — 改读 record.relatedThemeIds。
- `edge-mapper.ts`:③ about_theme 从 `state.memoryEdges` → 从 `memoryRecords[].relatedThemeIds`(并入 ① 风格)。
- `storage.ts`:`migrateMemoryEdges`(R4 迁移)→ 增量迁 memoryEdges 到 record.relatedThemeIds + normalize。
- `memory-candidates.ts`:consolidate 的 memoryEdges prune → 随 record 删自然消失。
- `privacy.ts` / `migration.ts`:memoryEdges count/purge — 退役后移除。
- 召回:`recallThemeAssets` about_theme 路径(投影源变,SurrealQL 可不变)。

## 4. 分阶段(每阶段独立可验、可回退;仿 P1 S0→P1a-d)

- **M1a(加法,零风险)**:MemoryRecord 加 `relatedThemeIds?: string[]`;`approve`/`updateMemoryRecordText` **双写**(同时维护 record.relatedThemeIds + 现有 memoryEdges);storage normalize 从 memoryEdges 回填 record.relatedThemeIds。读侧不动。全绿。
- **M1b(读切换)**:edge-mapper about_theme + context-pack 图引用 + 召回改读 `record.relatedThemeIds`(权威),memoryEdges 仅作影子比对(等价验证,仿 P1d 影子读)。surreal 跨进程 + 全量验证图遍历/召回等价。
- **M1c(下线)**:确认等价后删 `MemoryEdge` / `state.memoryEdges` / migrateMemoryEdges,清理 privacy/migration count。全量回归。

## 5. 风险

- 记忆召回(about_theme 图遍历 + context-pack graphReferences)行为变化 → 必须影子比对等价(M1b)。
- 隐私 purge / 审计 count 依赖 memoryEdges → 退役需同步(M1c)。
- 历史数据迁移(memoryEdges → record.relatedThemeIds)幂等 + 无损(M1a normalize)。
- 丢失边元数据(MemoryEdge.createdAt"记忆何时挂主题"):若产品需此审计,M1 应保留富边形态(反向:七类也升级带边 id),而非 record 内嵌——**需产品确认是否需要"资产入主题时点"**。

## 6. 为何不在 P2c 审查批次内做

P2c 批次是"修明确 bug + 低风险一致化"。M1 是 10+ 消费点 + 三阶段 + 数据迁移 + 召回等价验证的重构,非 bug(memoryEdges 现状功能正确)。混入审查批次会:① 放大单次 diff 与回归面;② 与 H1(persist)等 surreal 改动叠加难定位;③ 越过"边元数据是否保留"的产品决策。按本项目惯例(P1 系列分阶段 ff),M1 应独立执行。
